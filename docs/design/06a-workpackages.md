## 1. 阶段与初始人日

以下保留 v4.6 的初始量级估算，假设单人全职、熟悉所选技术栈、使用成熟组件并有 AI 辅助。人日包含实现、必要验证、契约和使用文档，不包含论文正文写作。它用于安排先后关系，不是进度报告，也不表示新增验证规格能够自动纳入原估算；第 2 节的成立条件须在 P0 核实，P0/P1 完成后依据真实接缝、参照资产和交付速度重估。

|阶段|范围|初始人日|
|---|---|---:|
|P0|接缝、参照规格、核心契约决定|5～8|

## 2. 估算前提与单列工作

估算成立需要可核验的首条参照源码位置、初始 commit 及独立验收资产修订，具体来源见[首条参照规格](../implementation/reference-chain.md)。P0 核实取得或建设资产所需的工作；没有证据时记为未就绪，不以选定 React/FastAPI/PostgreSQL 组合代替现成资产证明。

|估算前提|P0 必须核实的证据|不成立时的工作量处理|
|---|---|---|
|P0.1 接缝 2～3 人日|候选版本的受支持接口能较快成立；D06 第 2.2 节六张卡逐项有实际版本、输入、观测和能力结论|请求拦截、SDK 重试、序列化、检查点或同事务交接不兼容时，单列适配、版本更换及重新取证工作；涉及事务或调度职责改变先评审，不吸收到缓冲中冒充已覆盖|
|P0.2 参照准备 1～2 人日|已有可取得的样例、固定需求和独立验收资产，主要工作是核验、锁定及补足首条链路输入|区分核验现有资产与自行建设；样例取得或创建、需求冻结、独立验收资产准备、迁移/故障场景准备、实际机器及域名证书准备分别记录投入与剩余估算|
|客户端、拓扑与基础设施支持范围|按 D06 第 2.1、4.1、8 节列明实际 Windows/Linux、浏览器/Tauri/WebView、同机/独立 Runner、Compose、DNS/TLS、存储组合，注明组合数量及支持/受限/不支持依据|增加系统、客户端或基础设施组合时单列适配与验收；未核验组合保持未决，不能以单一浏览器或同机结果替代其他组合|
|首批扩展适配器范围|按 D06 第 7、12 节列明 Registry、外部 CI、通知和观测提供方的实际选型、数量、版本、权限与容量约束|每个新增适配器记录实现和验证工作包；不能把类别名称解释为支持所有提供方|

额外工作沿所属工作包登记，例如 P0.1 的适配子包、P0.2 的参照资产建设子包，保存触发原因、范围、估算区间与依据、责任人、实际投入、剩余工作和阻塞入口。没有足够依据时保持待估，不编造精确人日。P0/P1 退出分别更新各阶段合计、关键路径和剩余估算，说明与上述原始量级的差额；新增工作及支持范围变化不能全部静默吸收到约 25% 缓冲。可并行表示依赖允许，同时列出执行人数及共享资源限制，不因此减少单人总人日。

## 4. 关键路径与阶段记录

原始量级加入约 25% 的接缝返工和环境差异缓冲后为 156～254 人日；按每月 20 个有效工作日，单人全职约 8～13 个月，论文正文另计。这些数值保持为待核实前提下的规划基线，新增适配和资产建设等单列工作确认后重新汇总，不承诺维持原上界。关键路径为 SDK/事务接缝 → 可靠执行闭环 → 单 Agent 生产与证据 → 多 Agent 协作 → 恢复与运维完整性 → 最终产品验收。Desktop 随阶段交付；Linux 构建环境、执行器账本、客户端基础和适配器可在相应契约冻结后并行，真实机器验证、人类验收和集成仍遵守前置依赖。

统一阶段记录模板：

- 阶段/工作包 ID、原估算、实际投入、剩余估算。
- 估算前提和支持矩阵修订、组合/适配器数量、额外子包及其依据、重估日期与相对原估算的差额；尚不能估算的项明确标记待估。
- 未决决定、受阻范围、解决责任人与下一检查点。
- 已实现：附实现版本或 commit 及对象引用。
- 自动验证：附方法版本、输入集、环境、结果与证据引用。
- 人工验收：附验收人、范围、时间和结论。
- 未完成：列明剩余退出条件及其阻塞范围。

本文件保存阶段设计与估算模板，当前阶段及开放工作包见 [PROJECT_PLAN.md](../../PROJECT_PLAN.md)。记录模板中的实现、自动验证和人工验收只有在对应证据形成后才更新；不得从估算表或历史修订追踪推断当前进度。
