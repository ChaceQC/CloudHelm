# 预览与可选人测

本说明对应源码 `0.28.0`、新隔离库迁移 `0020_p2_previews`。工作流应用独立保持 `cloudhelm-hub/0.7.0`。规则依据 D03 §2.1、§2.3～2.3.1、D05 §4 和 [P0 预览决定](../decisions/p0/preview-access.md)；开发验证及支持限制见 [P2.4-01 记录](../acceptance/p2/p2-4-01.md)。

## 使用入口

Task 页的人工测试初始关闭，显示“未执行人工测试”，不会生成 Session、等待或通过证据。用户显式开启时，服务端要求当前已选用、检查通过且满足现有最终集成门禁的固定候选，推导其正式报告、InputSet、制品、策略、受控测试配置和合成数据修订。不能通过请求替换上游地址、验收输入或运行配方。

指定测试者须有项目读取和 `human_test.enter/pass/request_changes/skip` 中相应权限；项目所有者仍受“指定测试者”限制。维护入口可授予 `tester` 角色及所需动作，Agent 的动作上限未增加。当前界面默认指定开启者，API 可指定已登记人类。

准备/排队保持 `preparing`，不创建人工等待，也不开始人测期限。真实服务和受控访问就绪后，测试者明确开始本轮，创建业务等待，初始期限为 4 小时；人类等待不保留 AgentRun 或 DBOS 工作流。一次手动续期增加 2 小时，要求当前权限、同一环境、仍有效资源和能够覆盖总时限的原资源租约；不具备条件时拒绝续期。活动只刷新空闲时间，不延长硬期限。

30 分钟没有人类有效活动时记录提醒，5 分钟宽限结束或到硬期限时请求撤销和安全停止。健康探测、后台心跳不算人类活动。界面提供显式活动、续期、让出、取消和环境事实查询；提醒与回收由独立维护队列逐分钟检查，因此本轮不是精确到秒的提醒承诺。

“通过”“需要修改”“跳过”均由指定且当前有权的人类提交。跳过必须有策略依据和原因，记录 `skipped/not_run`；准备失败或未部署也可明确跳过，证据明确说明没有物理测试环境，不生成通过。未反馈、超时、失联、故障和取消都不会自动通过。提交时核对 Task、Session、候选及轮次，旧页面不能确认新轮次。反馈不要填写凭据；附件当前仅接受既有可核验引用，不提供任意附件上传。

需要修改时复用原开发工作项和持久通知；新候选必须重新自动验证，并由新轮次真实人测通过才能关闭人测问题。Task 已完成时生成绑定实际被测源码的关联草稿修复 Task，保留原完成报告；新 Task 的预算初始为零，后续推进须另获预算和授权。关闭等待不代表通过。Task 是否被人测阻塞依已固定策略判断；显式选择本候选的人测后，Release 也检查最新真实结论及适用性。

## 物理运行与资源

首批仅支持现有受控 notes 配方：

- 增量预览沿原开发环境命令提交 `preview=true`，仍由原工作流准备；成功后以原 `prepare_operation_id` 关联预览记录。当前只包含后端 HTTP，没有 HMR。
- 固定候选临时环境从可信构建查询读取前端、后端及 PostgreSQL 镜像身份，复核 InputSet、OCI 内容和受控运行配方，在独立数据集内迁移、初始化并探活。不会写入正式 EnvironmentBinding 或交付机器。
- 两者申请的资源向量、占账和硬上限均包含 `preview_slots=1`，共享现有宿主预算；原预留为零槽的开发环境须先确认停止再新建，不能偷偷补槽。实际 Runner 和池登记须支持该槽，否则明确排队/拒绝；本包不修改既有机器登记。
- 现有固定资源配方在人类等待期间保守占用整组物理额度，可能阻塞其他重任务；DBOS 队列槽与物理额度分别计算。增量环境保留原 2 小时资源期限；固定人测资源从实际准备申请固定截止，留出准备余量，准备超时进入停止核对，期限不得被查询或重试刷新。

执行意图与 DBOS 入队在同一事务内保存。已有物理日志只观察原身份，不因响应丢失重新准备。维护每轮有界处理 16 条环境；就绪环境继续核对物理事实，取消、输入失效、到期和让出先撤销入口，再走原停止路径。停止未知保持 `stopping` 和原占账；完整进程组停止及账本释放分别确认，磁盘保留继续遵循现有存储账本。通过证据不会因环境回收被改写。

## 受保护访问

客户端路线默认关闭。只有安装方受控的公开元数据文件 `CLOUDHELM_PREVIEW_DESCRIPTOR` 包含 `management_origin`、独立的 `preview_domain` 和通过 P0 契约检查的 `client_route`，且其 DNS/TLS、客户端运行时和六组独立证据真实适用时，才能发布访问入口。文件不存秘密；普通项目或客户端不能登记它。未配置时即使物理进程就绪，访问仍显示 `preview_route_unconfigured`。填写字段或引用本身不构成独立验收，本轮没有开放任何真实客户端组合。

每个实例分配独立且不复用的 HTTPS 主机名。管理资源地址为 `/preview/start/{environment_id}`，只有资源标识，不授予访问权。基础 Desktop 只显示该地址，不将票据交给主 WebView、原生命令日志或系统 URL。管理页面中的会话凭据只用于该可信文档的当前认证请求，不保存到 Web Storage。

管理页面取得不超过 60 秒的一次性票据，经顶层表单 POST 到固定平台路径 `/__cloudhelm/redeem`。票据不进入 URL、通知、模型上下文、普通查询或项目上游。数据库只存校验摘要，在授权行锁内原子消费并创建唯一专用会话；并发兑换只允许一次成功，已提交但响应丢失不会补发或创建第二份凭据。同申请重投只返回公开记录。

成功页设置 host-only、Secure、HttpOnly、SameSite=Strict 的 `__Host-cloudhelm-preview` Cookie，再由人类点击同源入口。平台路径不转交项目，代理移除平台 Cookie、Authorization 和内部认证头；禁用 Service Worker，首批拒绝 WebSocket/HMR/Worker。HTTP/SSE 请求使用受控 Runner 的固定 IPv4 映射，每次请求及在途流重新核对当前权限、实例、候选、轮次和期限。

实际 TLS 必须由可信入口提供真实 HTTPS ASGI scheme；不信任客户端的 `X-Forwarded-Proto`。预览 Host 在管理 API 之前截获，未登记的主机不能绕过管理 Host 边界。实际 DNS、证书、原始端口旁路、IPv6 禁用、浏览器 Cookie 行为和原生隔离仍属 P2.4-02 的直接证据。

撤销同事务记录原截止和原代理集合，并立即阻止新签发、兑换及后续授权；已有流执行关闭。ASGI 本机关闭只记本机事实，不能证明独立 TLS 入口的外部连接已经关闭，也不能单独结束撤销或重新签发。缺独立入口确认、控制失联或缺可信计时证据时保留 `revoking/pending_time_unknown`，不得宣称满足 3 秒失联、2 秒关流或 10 秒全部确认目标。显式重新授权须先收齐原访问关闭依据。

## API 与安装边界

人测入口为 `GET/POST /api/tasks/{task_id}/human-tests`、`GET /human-test-options` 和 `/api/human-tests/{session_id}` 下的 `ready/conclusion/activity/renew/yield/cancel`。所有写命令带原幂等键和当前 Task/Session 修订，回执顶层 `command_id` 复用 Desktop 日志机制。

普通预览使用 Task 下的 `candidate-previews/development-previews`；环境通过 `/api/preview-environments/{environment_id}` 查询并显式停止。公开查询不含内部上游或凭据。管理文档专用的 `access-request/access` 和 `/api/preview-authorizations/{id}/revoke` 不加入 Desktop 票据通道。

迁移新增人测会话、预览环境、授权和执行意图表，并补充 tester 角色。旧安装不会由 initialize 自动升级；不得把新源码直接用于旧运行库，也不得自行重启、清空或迁移现有原操作。新库开发验证、P2.4-02 隔离证据和原生/人工产品验收分别记录。
