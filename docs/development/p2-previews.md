# 预览与可选人测

11 月 1 日，本机 WSL 和 Windows 组合已登记一个预览槽并启动受控代理。**本机组合仅用于开发验证，正式客户端入口关闭。** 详见[本机记录](../acceptance/p2/p2-4-02-closeout.md)和[支持矩阵](../acceptance/support-matrix.md)。

新库目标见 [Hub 初始化说明](p1-hub.md#2-受控数据库初始化)。规则依据 D03 §2.1、§2.3～2.3.1、D05 §4 和 [P0 预览决定 r2](../decisions/p0/preview-access.md)。早期验证见 [P2.4-01](../acceptance/p2/p2-4-01.md)、[P2.4-02 首轮](../acceptance/p2/p2-4-02.md)和[隔离与原生验证](../acceptance/p2/p2-4-02-followup.md)。

## 使用入口

Task 页的人工测试初始关闭，显示“未执行人工测试”，不会生成 Session、等待或通过证据。用户显式开启时，服务端要求当前已选用、检查通过且满足现有最终集成门禁的固定候选，推导其正式报告、InputSet、制品、策略、受控测试配置和合成数据修订。不能通过请求替换上游地址、验收输入或运行配方。

指定测试者须有项目读取和 `human_test.enter/pass/request_changes/skip` 中相应权限；项目所有者仍受“指定测试者”限制。维护入口可授予 `tester` 角色及所需动作，Agent 的动作上限未增加。当前界面默认指定开启者，API 可指定已登记人类。

准备/排队保持 `preparing`，不创建人工等待，也不开始人测期限。真实服务和受控访问均就绪后，指定测试者明确开始本轮；服务端用同一个 `ready_at` 记录环境期限上限并创建会话的业务等待。初始期限为 `ready_at + 4 小时`，原租约不足以覆盖这段时间时不能开始。人类等待不保留 AgentRun 或 DBOS 工作流。

人测环境在确认前以原物理租约为上限；确认后，上限取 `ready_at + 6 小时` 与原租约截止中较早者。当前有权测试者可在初始期限内申请一次续期，只有同一环境和仍有效的原租约都能覆盖六小时总时限时才增加 2 小时。拒绝时保留会话原期限；获准也不刷新原租约或既有访问授权的截止。活动只刷新空闲时间，不延长硬期限。

30 分钟没有人类有效活动时记录提醒，5 分钟宽限结束或到硬期限时请求撤销和安全停止。健康探测、后台心跳不算人类活动。界面提供显式活动、续期、让出、取消和环境事实查询；提醒与回收由独立维护队列逐分钟检查，因此本轮不是精确到秒的提醒承诺。

“通过”“需要修改”“跳过”均由指定且当前有权的人类提交。跳过必须有策略依据和原因，记录 `skipped/not_run`；准备失败或未部署也可明确跳过，证据明确说明没有物理测试环境，不生成通过。未反馈、超时、失联、故障和取消都不会自动通过。提交时核对 Task、Session、候选及轮次，旧页面不能确认新轮次。反馈不要填写凭据；附件当前仅接受既有可核验引用，不提供任意附件上传。

需要修改时复用原开发工作项和持久通知；新候选必须重新自动验证，并由新轮次真实人测通过才能关闭人测问题。Task 已完成时生成绑定实际被测源码的关联草稿修复 Task，保留原完成报告；新 Task 的预算初始为零，后续推进须另获预算和授权。关闭等待不代表通过。Task 是否被人测阻塞依已固定策略判断；显式选择本候选的人测后，Release 也检查最新真实结论及适用性。

## 物理运行与资源

首批仅支持现有受控 notes 配方：

- 增量预览沿原开发环境命令提交 `preview=true`，仍由原工作流准备；成功后以原 `prepare_operation_id` 关联预览记录。当前只包含后端 HTTP，没有 HMR。
- 固定候选临时环境从可信构建查询读取前端、后端及 PostgreSQL 镜像身份，复核 InputSet、OCI 内容和受控运行配方，在独立数据集内迁移、初始化并探活。不会写入正式 EnvironmentBinding 或交付机器。
- 两种环境都需要预留一个预览槽（`preview_slots=1`），计入原宿主预算。已有环境的预留为 0 时，先确认该环境已经停止，再申请带预览槽的新环境。Runner 和资源池都必须登记该能力，否则申请排队或被拒绝。维护者应先在原账本核对占用，再按[本机登记记录](../acceptance/p2/p2-4-02-closeout.md#原账本与受控代理)使用专用入口；普通服务启动和预览申请不会改动登记。
- 现有固定资源配方在人类等待期间保守占用整组物理额度，可能阻塞其他重任务；DBOS 队列槽与物理额度分别计算。增量环境保留原 2 小时资源期限；固定人测资源从实际准备申请固定截止，留出准备余量，准备超时进入停止核对，期限不得被查询或重试刷新。

执行意图与 DBOS 入队在同一事务内保存。已有物理日志只观察原身份，不因响应丢失重新准备。维护每轮有界处理 16 条环境；就绪环境继续核对物理事实，取消、输入失效、到期和让出先撤销入口，再走原停止路径。停止未知保持 `stopping` 和原占账；完整进程组停止及账本释放分别确认，磁盘保留继续遵循现有存储账本。通过证据不会因环境回收被改写。

## 受保护访问

开放入口前，安装方应在受控文件 `CLOUDHELM_PREVIEW_DESCRIPTOR` 登记 `management_origin`、独立的 `preview_domain` 及通过 P0 契约检查的 `client_route`，并核对实际 DNS/TLS、客户端运行时和六组隔离证据是否适用于该安装。文件只存公开元数据，由安装方维护。没有有效配置时，访问返回 `preview_route_unconfigured`。

每个实例分配独立且不复用的 HTTPS 主机名。管理资源地址为 `/preview/start/{environment_id}`，只有资源标识，不授予访问权。基础 Desktop 只显示该地址，不将票据交给主 WebView、原生命令日志或系统 URL。管理页面中的会话凭据只用于该可信文档的当前认证请求，不保存到 Web Storage。

管理页面取得不超过 60 秒的一次性票据，经顶层表单 POST 到固定平台路径 `/__cloudhelm/redeem`。票据不进入 URL、通知、模型上下文、普通查询或项目上游。数据库只存校验摘要，在授权行锁内原子消费并创建唯一专用会话；并发兑换只允许一次成功，已提交但响应丢失不会补发或创建第二份凭据。同申请重投只返回公开记录。

成功页设置 host-only、Secure、HttpOnly、SameSite=Strict 的 `__Host-cloudhelm-preview` Cookie，再由人类点击同源入口。平台路径不转交项目，代理移除平台 Cookie、Authorization 和内部认证头；禁用 Service Worker，首批拒绝 WebSocket/HMR/Worker。HTTP/SSE 请求使用受控 Runner 的固定 IPv4 映射，每次请求及在途流重新核对当前权限、实例、候选、轮次和期限。

实际 TLS 必须由可信入口提供真实 HTTPS ASGI scheme；不信任客户端的 `X-Forwarded-Proto`。预览 Host 在管理 API 之前截获，未登记的主机不能绕过管理 Host 边界。实际 DNS、证书、原始端口旁路、IPv6 禁用、浏览器 Cookie 行为和原生隔离仍属 P2.4-02 的直接证据。

配置安装描述后，Hub 先按已登记的 `management_origin` 和 `preview_domain` 分流。管理地址仍执行原 Host 检查，`GET /health/live` 不依赖预览环境查询，只表示 Hub API 进程存活。预览实例子域必须查询环境并通过原授权及控制门禁；查询故障时拒绝访问，域外未知 Host 由原管理 Host 门禁拒绝。未登记安装描述时沿用原本机入口行为。

撤销同事务记录原截止和原代理集合，并立即阻止新签发、兑换及后续授权；已有流执行关闭。ASGI 本机关闭只记本机事实，不能证明独立 TLS 入口的外部连接已经关闭，也不能单独结束撤销或重新签发。缺少逐代理确认时仍为 `revoking`；Hub 时基不适用时显示 `pending_time_unknown`，时基适用且原截止已到则显示超时。显式重新授权须先收齐原访问关闭依据。

代理先封闭本轮收到的待撤销授权，再由单个后台任务逐条上报已观察到的关流结果。一条上报失败或超时后，后台任务继续处理本轮其他条目；控制轮询和封闭入口不等上报。失败条目仍待确认，后续轮询沿原授权及代理启动身份重投同一物理回执，原撤销截止时间不变。

## API 与安装边界

`0.28.1` 修正管理页内嵌脚本的转义，并仅对可信管理交付页使用 `Referrer-Policy: strict-origin`，使实际 Edge 顶层 POST 保留精确的管理 Origin。兑换完成页和项目预览仍使用 no-referrer；`null` 来源继续拒绝。控制查询超时缩为 1.5 秒，为 1 秒轮询后的 3 秒控制间隔留出余量，实际支持仍以直接计时证据为准。

`0.29.0` 为实际预览槽接入每实例宿主/转发ACL。root ResourceHost 的私有登记可添加 `preview_proxy_cgroup: "system.slice/<固定>.service"`；实际代理出站进程须由该root控制的systemd服务启动，普通同UID进程不能加入。缺配置或内核能力时拒绝预览网络准入，非预览路径保持原约定。规则绑定bridge ifindex及cgroup inode，服务重启后原网络不能静默换绑；实例显式禁用IPv6，5173仍不支持。

预览 HTTP 入口必须使用 `services.hub-api.preview_transport.PreviewServer`，由 h11 传输报告实际关闭；否则拒绝转发。CLI 的 UDS 或回环入口只记录本地关闭，外部入口使用该 Server 的真实 TLS 监听和物理回执记录代理确认。

### 可信计时

受控安装代码通过 `create_app(preview_clock_support=...)` 提供 [`PreviewClockSupport`](../../modules/workspaces/preview_timing.py)。只接受适用于当前 Linux `CLOCK_BOOTTIME` 的受审误差、速率及连续性证明，核对本次宿主启动标识、时钟源和休眠计数；虚拟化环境的连续性检查须覆盖宿主暂停及见证中断。安装方提供线程安全、有界且不阻塞的实时检查，见证失效后不得在同一计时纪元重新建立基准。远端许可的 RAW 证明、NTP 状态、时钟分辨率及单次读数差都不能代替该输入。默认 CLI、安装描述和 HTTP 请求都不提供可信计时证明。

同进程的 Hub 和代理分别建立计时纪元。Hub 以撤销事务提交前读数为起点，以接受物理关闭确认的读数为终点，按同一纪元的保守上界核对 10 秒；API 发起的环境停止与显式撤销使用同一个 Hub 时钟。另一个进程写入的撤销或重启后留下的旧纪元仍可核对物理关闭，原时限为 `pending_time_unknown`，截止时间不刷新。代理用自身读数核对 3 秒控制间隔、首次失败后 2 秒关流和最后有效控制后 5 秒上限。实际关流回执的内部 `proxy_timing` 记录上界及未知或超限结果，重投沿用原回执。两者的单调读数不做跨机或跨纪元相减。

缺少有效证明时，Hub 拒绝新票据（`preview_clock_unavailable`），代理封闭新请求并终止已登记的流；撤销和关闭事实仍可查询。当前宿主与取证限制见 [E06c 记录](../acceptance/p2/p2-4-02-e06c.md)。

### Desktop 与 HTTP API

预览环境为 `ready` 且安装方已登记 `tauri_windows_webview2` 时，Windows Desktop 显示“打开隔离预览”。原生层从当前 Hub 读取公开地址，使用独立容器认证。兑换尝试后，容器限制在该实例来源。公开查询只提供可选的 `entry_origin` 和 `client_route`。

主窗口收到 `preview.revocation_requested` 或 `preview.stop_requested` 后，请求原生关闭已打开的预览窗口。同一项目、同步流和权限修订下，刷新快照期间继续消费事件，续订从本机最后消费的事件游标继续。切换项目或旧订阅范围失效时请求关闭旧窗；如果原打开请求晚到，按返回的窗口标识补发关闭。切回原项目需重新显式打开预览。

原生层在收窗后尝试删除专用分区。主窗口收到 `preview-cleanup` 回执后，按窗口标识显示已删除或清理失败。失败提示说明分区可能仍留在本机，其他窗口清理成功时仍保留这条提示。提示不依赖当前项目或 Hub 连接，可逐条关闭。强制退出后的残留分区不会复用。

本机收窗、专用分区实际删除和服务端逐代理关闭需要各自的证据。本机验证还缺服务端撤销到 Windows 窗口关闭和分区删除的完整结果，以及同一正式候选的旧轮次、重建和重连结果。

人测入口为 `GET/POST /api/tasks/{task_id}/human-tests`、`GET /human-test-options` 和 `/api/human-tests/{session_id}` 下的 `ready/conclusion/activity/renew/yield/cancel`。所有写命令带原幂等键和当前 Task/Session 修订，回执顶层 `command_id` 复用 Desktop 日志机制。

普通预览使用 Task 下的 `candidate-previews/development-previews`；环境通过 `/api/preview-environments/{environment_id}` 查询并显式停止。公开查询不含内部上游或凭据。管理文档专用的 `access-request/access` 和 `/api/preview-authorizations/{id}/revoke` 不加入 Desktop 票据通道。

迁移新增人测会话、预览环境、授权和执行意图表，并补充 tester 角色。旧安装不会由 initialize 自动升级；不得把新源码直接用于旧运行库，也不得自行重启、清空或迁移现有原操作。新库开发验证、P2.4-02 隔离证据和原生/人工产品验收分别记录。
