## 2. 版本规则

1. 总体设计使用 `vM.N`，配套专题使用 `vM.N.P`；前两位必须相同。当前总体设计为 `v4.3`，详细文档为 `v4.3.0`。
2. 同一总体基线内，专题澄清、补充与修订递增第三位；可以独立递增，但同时更新下方基线清单及依赖文档的兼容说明。
3. 改变三端边界、状态所有权、安全不变量或交付语义等总体决策时，需显式评审是否升级总体版本，不以增加第三位隐藏不兼容变更。
4. 总体版本变化后，配套文档完成核对才可迁移到新的前两位，初始修订号为 0；旧文档归档，不自动批量改号假定兼容。
5. 版本写入正文页首，专题文件名保持稳定，避免修订号变化使链接失效。文档版本不等于软件发布版本、数据库版本或执行 `schema_version`。

## 3. 文档维护

修改设计规则时，同步更新负责文档、受影响引用、验收要求和版本清单。实现进度及实际验收结果在交付记录中维护，设计正文说明系统结构、行为和约束。

## 4. v4.3 基线变更

- 持久调度采用 DBOS Python；FastAPI 使用 DBOSClient，单 worker 承载运行时，默认无需独立编排服务器或 Conductor。
- 业务与 DBOS 系统表采用同一 PostgreSQL 数据库的不同 schema，工作流入队与业务状态使用同一事务；事件同步和其他非原子交接继续使用 Outbox。
- 取消自研 WorkflowJob 调度状态机，保留业务关联及 Operation/Attempt/StepExecution、物理资源和远端账本。
- 补充 DBOS 队列与资源分工、消息等待、检查点重放、当前授权检查、旧备份恢复门禁和工作流升级策略。
- P0/P1 冻结 DBOS 能力与兼容矩阵，P1/P2 提前核验容量和故障语义，4GB 仍为待验证目标。

D01～D06 已按本次 DBOS 选型交叉修订，统一作为 v4.3.0 基线。文档升级不表示 SDK 已安装、平台已实现或容量已验收。完整旧版见 [v4.2 总体设计](../../../v4.2/云舵%20CloudHelm%20毕设设计书%20v4.2.md)和 [v4.2.0 详细设计索引](../../../v4.2/docs/design/README.md)。
