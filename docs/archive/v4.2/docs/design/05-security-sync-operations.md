## 1. 身份、权限与威胁边界

|身份|允许的职责|隔离要求|
|---|---|---|
|User / Desktop Session|获授权的项目操作、审查与审批|登录凭据保存在 OS 凭据存储，不进入 SQLite 普通缓存|
|Agent 身份|代表明确用户与 Task 的受限工具调用|能力不超过用户、任务与资源策略的交集，不能代替人类批准|
|Git 服务|仓库元数据、受控提交与远端认证|不运行仓库提供的宿主脚本|
|Runner|开发沙箱、进程、资源与受限构建|宿主接口不向 Agent 或生成代码开放|
|Remote Agent|批准的受管部署、诊断和固定 runbook|machine identity 与人类/开发身份分开，能力绑定目标|

采用 system/project/environment scoped RBAC，结合资源归属和当前策略。owner、developer、reviewer、operator、deployment_approver、auditor 是建议角色；服务端决定权限，UI 隐藏按钮不能替代检查。

仓库、附件、网页、日志和其他 Agent 的内容作为数据处理。Gateway 验证能力、路径、输出限额及授权，不能因工具标记为只读而忽略敏感数据访问。

初期面向受信任平台所有者管理的项目，不宣称普通 Docker 能隔离任意敌对租户。需要敌对多租户时增加独立 Runner 或更强沙箱，并重新验证宿主、网络与缓存边界。

Remote Agent 的 Docker 管理权限具有较高宿主影响面。项目命名空间用于防误操作与资源归属，不等于可以抵御具有 Docker 管理权限的恶意主体。

## 2. 配对、通道与能力

初次机器配对使用短期单次挑战，绑定目标、操作者和有效期，建立独立 machine identity。后续凭据支持轮换和吊销；执行器校验当前获准的 Hub incarnation、操作摘要、资源、期限和代次。

Desktop、Runner 和 Remote Agent 通道均认证并验证 TLS 对端。SSH 引导只执行已说明的安装步骤，完成后日常操作统一走执行协议，避免重复部署路径。

固定只读诊断可按策略自动运行；重启、配置修改、回滚和数据操作必须有对应授权及审批。高风险权限被撤销后停止新的变更，已在运行的操作按 D02 安全停止或核对，不能删除执行记录假装未发生。

## 3. 凭据版本与秘密材料

SecretReference 至少包含用途、所属项目/环境、提供方、不可变 version_id、状态及访问策略。实际秘密值由受控凭据模块解析，模型只接触用途和不含值的引用。

首版可采用加密持久存储，解密密钥与数据库备份分开管理，通过受限服务身份访问；支持外部凭据后端时，adapter 必须说明版本固定、轮换、吊销和恢复能力。若后端只能返回 latest，不满足固定版本要求，需经受控机制固化版本或拒绝相应部署。

轮换创建新版本，明确旧版本是继续有效、停用还是已撤销。DeploymentPlan 固定版本引用，执行前再次检查可用性；不能自动把旧计划解析为新值，也不能回滚到已撤销凭据。

目标端仅持久保存当前运行及明确保留恢复所需材料，使用最小文件权限和适合的加密/挂载方式。业务独立重启需要能在不联系 Hub 的情况下读取获准材料。环境变量等注入方式的可见性应在安装说明中如实列出，不承诺对目标 root 隐藏。

读取、修改和排障配置时不得显形输出密钥。禁止实际值进入模型输入、聊天、审计正文、客户端 SQLite、可分享制品及普通日志；受保护的凭据存储和目标运行所必需的受限材料属于专门管理范围。审计只记录版本与操作身份，不上传容易枚举的秘密明文哈希。

脱敏是补充措施；私有依赖令牌不复用生产凭据，生成代码不能访问长期管理凭据。秘密暴露处置需轮换/吊销并按保留策略清理受影响内容，不以删一条聊天消息宣称已经消除外部传播。

## 4. 预览域名与浏览器隔离

管理端与预览端必须使用不同主机名，优先不同站点域；每个预览实例独立 origin。不同端口不隔离 Cookie，因此禁止仅用同主机不同端口实现管理与预览隔离。

管理 Cookie 使用 host-only、Secure 和 HttpOnly，并配置适当 SameSite、CSRF 防护及受限 CORS。管理会话不通过父域 Cookie 与预览共享。预览代理仅转发必要的预览凭据，移除管理认证材料；管理 API 不向任意预览域开放带凭据访问。

访问票据短期有效、绑定用户、实例和权限，交换为预览专用会话后从地址中移除，避免进入 Referer 和应用日志。路由绑定沙箱、端口、协议及有效期，不能通过用户提供任意上游地址绕过访问范围。

Desktop 使用无 Tauri 原生能力的独立受限 WebView 或外部浏览器；拒绝主窗口 IPC 和跳转到具备原生能力的页面。终止预览时撤销路由、票据与预览会话，并清理实例相关存储。

安装预检要求管理和预览域名、DNS、证书及客户端信任链均可用。可使用公网域名或受控内网 DNS/证书，但不能默认忽略证书错误。只有 IP 的环境须先完成受控名称与信任配置；未配置时预览显示不可用，不能把该配置标为完整验收通过。

## 5. 数据、事件与 API 契约

PostgreSQL 保存当前业务状态、执行索引、EventLog、Audit 和 Outbox。大文件、截图、报告及长工具输出进入受控制品存储；遥测使用有界聚合或可选专业后端，不逐采样写业务事件。

|资源|主要 API 范围|
|---|---|
|项目与任务|/api/projects、/api/tasks、工作项和 pause/resume/cancel 命令|
|协作|会话、messages、decisions、AgentSession inbox、ContextPackage 与请求记录|
|开发与集成|workspaces、sandboxes、previews、integrations、merge-queue、verifications、reviews|
|交付与运维|release-candidates、releases、deployments、remote-targets、environments、operations、incidents、observations、drifts|
|授权与同步|auth、role-bindings、approvals、snapshot、events|

P0 冻结完整路径、请求响应 schema、权限及错误语义。写命令支持幂等键和必要的 expected_version；响应返回业务资源及异步操作位置。冲突、过期计划、资源不足、权限不足和结果未知分别编码，不统一变为普通服务器错误。

schema_version 管理 API/事件/执行协议兼容，软件版本独立管理。不兼容时拒绝新变更并显示升级要求；设计文档版本不参与网络协议协商。

## 6. 快照与事件流无缺口恢复

业务事务写 Outbox。分发器读取已提交 Outbox，在独立短事务中锁定持久流计数器，分配递增游标、保存 DispatchEvent 并标记该 Outbox 已分发；全部同事务提交。轻量模式单分发者，未来多分发者也必须保持这一提交顺序约束。

不能使用业务表自增 ID 直接推断提交顺序。DispatchEvent 游标只表示分发顺序，事件同时携带 aggregate_id、aggregate_version、event_id、schema_version 和授权范围。

snapshot 在同一个一致性读取视图中读取已提交分发游标 C 与授权业务状态，返回状态、版本、删除墓碑和 C。客户端随后接收游标大于 C 的事件；快照里已包含但尚未分发的变化可能再次出现，以聚合版本去重，允许重复但不丢变化。

删除墓碑防止迟到的创建/更新事件复活已删除资源。墓碑只在相关 Outbox 全部分发且相关事件已早于可接受重放窗口后清理；资源 ID 不复用。大快照分页使用同一已冻结快照标识，不能逐页读取不同时间的状态；快照生成和保留有大小及期限限制。

游标过期返回重建指令。Hub 从旧备份恢复后使用新的流身份，旧客户端游标强制重新建立快照，不能把新流数字当作旧流的延续。

订阅、补发和快照均按当前权限检查。权限变化使相关订阅关闭并触发缓存范围重建；在线客户端清理撤销范围，离线客户端在下一次连接时处理。不能承诺服务端立即抹除已离线设备上曾获授权的数据，客户端缓存仍需本地保护和保留策略。

## 7. Desktop 产品行为

主要视图包括项目、需求、团队职责与依赖、代码 diff、验证报告、预览、部署及 Incident。默认展示目标、关键决策、阻塞、交付和费用；执行尝试、输入引用和原始输出在详情中可追溯。

用户补充需求产生版本与影响分析；暂停和取消展示执行器确认进度，不立即伪造所有任务停止。审批页分别展示起始环境、目标制品、配置版本、数据库影响、停机与补偿范围。

部署页区分期望版本、每服务实际版本、观测时间和历史操作结果。等待资源、等待回复、等待人工决策和执行未知具有不同恢复提示，不要求用户手工编辑内部租约或数据库状态。

Desktop SQLite 仅保存草稿、界面设置、可重建缓存及游标，权威状态在 Hub。文件上传下载经授权 API，桌面端不安装或运行项目工具链。

## 8. 观测、漂移与 Incident

Remote Agent 上报服务标识、镜像身份、非敏感配置摘要、secret 版本标识、健康、最近 Operation、执行代次和观测序号，分别保存 observed_at、received_at 和来源。按代次及序号处理迟到数据，不按到达顺序覆盖新状态。

基础观测通过容器、日志与网络探测完成。业务应用可以提供 /health、/ready、/metrics、优雅退出及受鉴权诊断接口，具体地址和探测方式写入运行契约；不强制业务引入 CloudHelm SDK 或共用平台数据库。诊断查询同时限制目标地址、权限和输出，避免成为访问任意内网服务的通道。

DesiredState 由 delivery 管理；ObservedState 和 DriftRecord 不修改历史 Release。默认报告漂移，恢复批准版本或接受外部变更均须走受控流程。无法验证来源的外部镜像不直接作为可信回滚版本。

管理通道离线显示最后观测及未知状态，独立 HTTP 探测另行呈现。重连先同步实际状态、未完成操作和代次，再处理仍有效的请求；过期请求不得作用于已经变化的容器。

日志在目标端轮转，初始查询上限为 500 行、1MiB，并限制时间窗、并发和尾随期限。需保留的证据脱敏后进入制品存储。默认每 30 秒采样，1 分钟聚合保留 24 小时、5 分钟聚合保留 7 天，实际参数依容量修订。

指标限制集合、标签基数、全局行数和字节配额；接近上限时降采样并标记缺口。仅状态变化与 Incident 进入业务事件，原始采样不进入 EventLog。需要长期数据时接入 Prometheus/Loki 等 adapter，查询仍返回来源和数据窗口。

告警按分组、持续时间、去重、静默、冷却和恢复规则创建/更新 Incident。运维 Agent 使用有界证据提出假设；固定只读诊断可自动执行，有副作用操作执行获批 runbook。需要代码修复时创建关联 Task，不重新打开原完成任务。

## 9. 备份与旧控制面恢复

备份覆盖数据库、权威仓库或必要镜像、制品索引与必要内容、凭据恢复安排，以及恢复所需的版本记录。数据库与文件内容通过备份清单引用一致版本；暂缺的制品明确标记不可用，不把索引存在当作内容存在。

恢复流程：

1. 隔离或停止旧控制面写入，新 Hub 以 recovery 模式启动，暂停部署和其他新副作用。
2. 校验备份、代码/制品引用和凭据可用性，生成新的控制实例身份；不能仅从旧数据库计数器继续分配代次。
3. 通过获授权的恢复流程与各执行器建立新 incarnation 的信任，执行器持久保存并拒绝旧 incarnation 新命令。
4. 按 D02 核对旧进程、本地账本、实际服务、数据库版本和资源占用；旧 incarnation 的既有进程仍须确认结束或纳入接管。
5. 将恢复的 Outbox 与远端事实逐项对照，已完成操作补录，未知操作保持核对；不批量重放旧队列。
6. 建立新的有效环境状态与流身份，重新评估待执行计划、审批和凭据，完成对应资源核对后才恢复新变更。

恢复授权不能由旧数据库里一条“恢复成功”记录自行证明。需验证目标身份和恢复操作者，旧实例隔离、凭据轮换及目标确认形成审计证据；随机生成一个 incarnation 字符串不足以建立信任。

Remote Agent 丢失本地账本时以新执行器身份重新接入，禁止报告所有旧操作均未执行。离线目标保持受限状态，不妨碍已部署业务继续运行；不能为了让 Hub 显示正常而停止业务。

## 10. 升级、卸载与验证

Desktop、Hub、Runner、Remote Agent、业务项目分别升级，安装记录包含兼容矩阵。升级期间按执行协议处理未完成操作，数据库迁移与二进制回退能力如实说明。

卸载单个业务项目只作用于绑定资源，默认保留需恢复的数据卷与记录，不删除 Hub、Remote Agent 或共享审计。清除实际凭据材料需结合仍在运行的服务及回滚策略处理。

安全与运维验收覆盖身份、凭据、预览、同步、观测、备份及升级，验收要求见 D06。备份验收应实际恢复数据并核对远端状态。
