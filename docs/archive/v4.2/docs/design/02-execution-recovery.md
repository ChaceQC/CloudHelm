## 1. 责任与共用范围

Workflow 负责持久任务领取、唤醒、定时和恢复调度；领域服务决定允许执行什么以及结果对业务意味着什么；Gateway 校验当前授权、参数和审批；Executor 执行受限操作并保存事实。

开发 Runner 与 Remote Agent 共用操作身份、步骤记录、查询、取消和代次规则，但使用独立能力集。不得借共用协议允许开发身份调用部署工具，也不要求所有工具都支持自动补偿。

API 在短事务内登记业务请求、事件和 Outbox，返回业务标识及异步状态位置。不在 HTTP 请求事务内等待长命令。内部工具可进程内调用，不要求全部包装成 MCP 服务。

## 2. 操作、尝试与步骤

|对象|关键字段|含义|
|---|---|---|
|Operation|operation_id、idempotency_key、kind、request_digest、scope、target、authorization_ref、deadline、状态|一次不可变业务执行意图|
|ExecutionAttempt|attempt_id、operation_id、hub_incarnation、resource_generation、executor_id、开始/结束、结果|某执行器的一次执行或接管尝试|
|StepExecution|operation_id、step_id、input_digest、适用资源、状态、前置/后置证据、尝试引用|可独立核对的具名步骤|
|ProcessBinding|attempt_id、step_id、容器/进程组身份、启动标记、资源预留、最后查询|本地真实进程与持久记录的对应关系|

幂等键按调用者及业务资源确定作用域。同键同请求返回原 Operation；同键不同摘要拒绝。重投或接管沿用 operation_id；真正改变业务意图需新 Operation 并重新验证授权。

StepExecution 的唯一键为 operation_id + step_id；重试不生成一个无关联的新步骤绕过去重。不同执行尝试追加历史，不覆盖“已经成功”的证据。

## 3. 状态与结果

Operation 使用 queued、running、cancel_requested、needs_reconciliation、succeeded、failed、cancelled。部分服务更新属于 Deployment 的业务结果，底层 Operation 同时提供步骤向量及最终失败原因。

|步骤状态|语义|恢复行为|
|---|---|---|
|planned|尚无副作用意图落盘|校验后可执行|
|started|执行意图已持久化，副作用可能开始|先查询，不能当作未执行|
|succeeded|后置条件和结果已持久保存|复用结果，不重跑|
|failed|已确认失败及其已知影响|按该工具声明判断是否可重试|
|unknown|无法确认实际影响|核对或人工处理|
|cancelled|已确认未开始或已停止，并保存已发生影响|不表示撤销已有变更|
|skipped|因前置失败等明确原因未执行|记录原因，不伪造成功|

每种工具必须声明结果查询方式、重试类别、取消方式、超时、输出上限及补偿能力。查询不到记录只有在可信且完整的执行账本中才可解释为未执行；执行器记录丢失不满足这个条件。

## 4. 本地持久执行记录

Runner/Remote Agent 使用本地持久账本保存收到的操作、授权摘要、执行代次、步骤和结果；首版可使用 SQLite 事务与适当的同步持久性设置。账本不与业务容器临时文件系统共生命周期，不保存模型上下文或实际密钥。

开始有副作用的步骤前先持久登记 intent，再启动命令并保存可查询的进程身份；执行后验证后置条件并持久记录结果，最后回报 Hub。记录 intent 与启动进程之间仍存在崩溃窗口，因此必须使用稳定的容器/进程组标识和实际状态查询，不能依靠这两次写入宣称 exactly-once。

数据库迁移先查询业务数据库的迁移账本与执行锁。事务性迁移尽量在同一数据库事务提交业务变更与迁移版本；非事务性迁移提供可核对的分步标记和人工恢复说明。Remote Agent 顶层成功标记不能替代数据库自身证据。

账本磁盘不足时拒绝启动新变更；不能先执行，再期望稍后补上记录。短期离线期间保留待上报结果，补报按操作和结果标识去重。

## 5. 租约、代次与接管

需区分三个概念：调度租约决定谁可领取工作；资源执行代次拒绝旧控制者的新命令；物理执行占用表示旧进程是否仍在修改资源。ConversationEpoch 与以上三者无关。

执行命令携带已注册的 hub_incarnation 和目标资源的单调 generation。执行器仅接受当前获准的 incarnation，并持久保存每个资源已接受的 generation。相同代次仍须校验 operation_id 和请求摘要，不能被其他操作复用。

增加 generation 不能自动停止旧进程。执行器对同一冲突资源持有本地执行锁，新命令即使代次更高，也须先核对旧进程；仍在执行的迁移不能仅通过拒绝旧回执就变为可重入。

接管顺序：

1. 将调度工作登记为待核对，停止该冲突资源的新启动。
2. 查询执行器账本、进程组/容器及实际资源状态。
3. 已完成则补记结果；仍执行则继续观察，或在允许的安全点停止。
4. 确认停止后记录已发生影响及步骤边界，再判断剩余步骤是否允许继续。
5. 重新验证授权、期限和资源条件，为新的实际尝试分配代次；旧尝试结果只作为历史证据。

未确认旧占用解除前，ResourceReservation 为 orphaned/reconciling，不能被重新分配。Executor 无法联系时允许影响范围外的工作继续，对冲突资源保持阻塞。

本地锁解决受管执行之间的串行化，不能阻止外部管理员直接操作 Docker 或数据库；这类变化由前后置条件检查及漂移识别处理。

## 6. 领取、投递与并发

PostgreSQL 以短事务和 SKIP LOCKED 领取就绪 WorkflowJob，记录 lease_owner、lease_until、attempt 和 expected_version。续租使用条件更新；过期工作先进入查询恢复路径。

Outbox 分发允许重复，接收方先完成幂等登记再执行。通知仅用于加快唤醒，周期扫描补偿通知丢失。不得把消息队列的 ack 当作远端副作用完成证据。

取消、状态查询、心跳和结果接收使用有界的控制请求容量，不与长构建共享阻塞调用。单 worker 通过异步 I/O 管理外部模型和执行请求；阻塞 SDK 或本地库调用需隔离，不能堵塞续租循环。

同一环境的变更通过 D04 的环境绑定锁串行；跨环境共享的主机资源单独管理。多个锁按固定资源键顺序申请，申请不到时释放未使用的预留并返回等待，避免循环持锁。

## 7. 超时、暂停和取消

deadline 区分允许开始的期限及操作最大执行时长，具体字段在协议 schema 中分别表示。签发端和执行端检查时钟偏差；期限不可信时拒绝新变更并报告时间问题，不能自行延长授权。

模型超时不自动取消已经启动的工具。用户暂停停止新工作，在安全点让出执行；用户取消登记 cancel_requested，由执行器返回“未开始”“已停止且存在影响”“仍在安全停止中”或“状态未知”。只有可确认的前两类才结束相应尝试。

运行测试等可终止的进程可按已配置的宽限期停止整个进程组；迁移和数据恢复按工具语义处理，不能为了释放资源强杀后宣称无影响。补偿作为获批的具名步骤记录，不擦除原失败。

## 8. 保留窗口与清理

已完成操作去重记录的保留期至少覆盖命令可接受期限、最大重投时间及允许时钟偏差。命令过期后也必须拒绝，不能因记录已清理而重新执行。

未完成、unknown、未确认停止及仍被业务/恢复引用的记录不按普通 TTL 删除。取消墓碑保留到所有相关命令不可再被接受；历史精简保留足以拒绝重放的身份和摘要。

目标端重新安装或执行账本丢失时产生新的 executor 实例身份，不能沿用旧身份并声称“查无记录就是没执行”。重新接入先核对运行资源，再由授权恢复流程决定可继续的操作。

## 9. 工具恢复分类

|工具类别|允许策略|禁止行为|
|---|---|---|
|纯查询|有界重试并标记观测时间|将过期数据当作当前状态|
|确定性文件/容器创建|按稳定身份及摘要查询，核对后复用|同名不同输入静默覆盖|
|构建|查询既有 BuildRun/进程；确认结束后按预算新建尝试|回执丢失即重复启动|
|外部 CI|按关联 ID 查询；不可识别时人工核对|无法查询时盲目触发第二次|
|部署/配置|按计划基线和步骤核对|使用过期计划继续修改新版本|
|数据库迁移/恢复|数据库账本、锁、后置检查或人工核对|仅靠 Operation 未成功就重复执行|

## 10. 协议实现与验证

执行 schema 独立包含 schema_version、operation_id、attempt_id、step_id、scope、target、授权引用、incarnation、generation、输入摘要和期限。认证保护消息完整性，字段校验不替代传输认证。

P0 冻结消息 schema 与兼容规则，P1 验证操作调度、执行接管及取消，P2 验证迁移的持久性与恢复。执行验收同时记录数据库状态、实际进程和资源变化，验收要求见 D06。
