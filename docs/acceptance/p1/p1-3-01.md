## 2. 退出条件映射

|退出项|实现与实际结果|
|---|---|
|共享宿主 Hub 原子整组预留|真实池行锁；两个不同用户/项目与两个 Runner 并发申请，1 个接受、1 个容量拒绝；命令/预留/事件/Outbox 各增加一次。调用方回滚四类记录全部回滚|
|注册/能力匹配|真实宿主唯一池约束；维护角色注册，两运行角色不能修改预算 JSON。CPU period/目标 Runner 不匹配和过期请求拒绝；不复制每 Runner 的物理预算|
|重复投递与本地持久确认|两个实际进程向同一 SQLite/启动锁投递原请求，只有一条接受记录；同身份返回原结果，不同摘要拒绝；另一已注册 Runner 的超额请求持久关闭未启动|
|接受后回执丢失|丢弃首次返回并重建 Runner 对象，Hub 按原身份从 SQLite 恢复接受回执；没有第二份预留/进程|
|实际硬限制|父组 `cpu.max=50000 100000`、`memory.max=134217728`、`memory.swap.max=0`、`pids.max=32`，真实容器进程在其子组；全部可写 tmpfs 合计 8,388,608 字节，实际写满 ENOSPC、额外线程创建被 PID 硬限拒绝，根只读且无宿主 socket|
|停止未知保守占账|故障注入只丢失真实运行进程的停止/观察通道；进程实际仍运行，Hub orphaned 且全额占账。恢复通道后核对原进程，不重新启动；确认容器/整个组/tmpfs 移除后释放，最终占账 0|
|启动前当前门禁与封闭|申请后真实 Task 取消，启动时重新检查并在原本地锁内持久 closed_unstarted；晚到重复启动仍封闭，未创建物理进程|

reserved、active、releasing、orphaned 始终参与 Hub 和本地容量核算。停止或磁盘事实未知不退账；本轮没有分维释放/保留或跨机器原子事务的通过结论。

## 3. 方法修正及收尾

[首次原结果](validation-resources-r1-attempt1.json)停在迁移约束命名漂移；[第二次](validation-resources-r1-attempt2.json)停在池行锁 UPDATE 权限不足；均未开始物理执行。迁移固定 DDL 已与 ORM 对齐，运行角色仅新增锁列 UPDATE，不能写预算配置。[第三次](validation-resources-r1-attempt3.json)通过准入/本地确认并启动真实组，但观测侧复用了 UID1000 的旧 Docker 客户端目录；旧方法失败不改写，实际资源已在 finally 确认回收。最后一轮方法改用自己的空私有 Docker 配置目录，绑定新输入后完整通过。

最终数据库及私有夹具清理 complete；容器、slice 和 tmpfs 已移除，资源占账为 0。方法在物理停止不确定时保留本地账本现场，不让数据库夹具清理删除未知操作的依据。本轮复用已加载镜像，没有新增项目开发镜像或淘汰镜像的删除对象；没有全局 prune。

[r1 输入](input-set-p1-3-01-r1.json)及[r1 通过结果](validation-resources-r1.json)保留原字节。r2 仅补齐可追溯操作/环境引用，并在当前源码移除一个未用导入；因此固定新输入后再次执行同一组退出场景，不将 r1 的旧输入摘要改写为当前候选。

## 4. 支持边界

本轮给出同机共享池、双 Runner 注册和跨进程持久投递的证据，首个实际后端为固定镜像/固定配方的封闭 scratch 资源组。128MiB、0.5CPU、32PID 和 8MiB 是方法输入，不是整机容量或 4GiB 池结论。P1.2 的镜像构建、持久数据与缓存仍按其旧隔离组合运行，不因本轮协议出现而自动宣称全部写入者已纳管。

资源调整、分维释放/磁盘保留、4GiB/5GiB 与 7GiB 残留、两阶段 Compose 由 P1.3-02 承接。s2413 安装/配额、独立物理机器和跨机传输、Desktop、原生与人类验收未执行。旧数据库不自动升级；历史证据只适用于原候选，不由当前版本追认。
