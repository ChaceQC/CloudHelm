## 4. 支持与证据边界

- 环境为 WSL Ubuntu-24.04、Linux `6.18.33.2-microsoft-standard-WSL2`；Python `3.12.13`、PostgreSQL `16.13`、DBOS `3.2.0`、SQLAlchemy `2.1.4`、psycopg `3.3.6`、Pydantic `2.14.1`、FastAPI `0.143.0`、Uvicorn `0.54.0`。Hub 源码与独立工作流应用版本为 `0.1.0`，业务迁移为 `0001_p1_1`。
- 测试数据库使用固定镜像、loopback `55433`、tmpfs、独立角色及随机私有凭据；API 使用受限 Linux UDS。API 每进程普通/控制池 2+1，单 worker 为业务 2+1、系统 4、额外监听 1；两个 API 加单 worker 配置上限 14 条应用连接。连接采样不等于整机容量验收。
- `dbos_schema_version` 为 null。支持依据是固定 SDK、受控同版初始化及公开启动核验，不宣称获得 SDK 未公开的精确系统版本或跨版本升级保证。
- Task 正向完成使用 `purpose=protocol_validation` 的受控合成来源及真实持久事实读取。它证明完成事务、权限、版本、唯一报告和并发规则，不证明已完成真实代码开发、构建、独立验证或人类测试。普通 HTTP 不能上传完整完成事实或可信布尔值。
- 初始业务工作流真实记录 `blocked/capability_not_enabled`；后续构建与 Agent 功能尚未接入。取消不要求开发验收材料齐备，未知物理操作则继续保持阻塞；合成封闭证据仅核验消费规则，不替代执行器的实际停止/封闭验收。

- GitHub `check` 覆盖结构、UTF-8、锁、源码/契约、HTTP 快照和参照构建；数据库/HTTP/Task/worker 的实际开发证据以本记录方法为准。s2413 安装与物理配额、独立目标交付、Desktop 原生和人类验收均未执行。
