# A00b 候选读取独立断言

预期来自用户指定的架构细化方案 `docs/architecture/2026-11-19-agent-architecture-detailed-design.md` §3.3、§10.1、§10.2 与下列样例约定，独立于被测实现和运行结果。A00b 主负责人在配套输入记录中登记准确提交 SHA、树清单摘要、队列条目与候选/尝试 ID、InputSet 引用和验收资产摘要。路径相对隔离参照项目根目录；样例中的 `\n` 表示一个 LF，文件字节为 UTF-8。

样例：`B0` 的 `backend/app/routes.py` 便签查询使用 `id.asc()`；`D1` 从 `B0` 只将该表达式改为 `id.desc()`。`T1` 从 `B0` 只新增 `docs/a00b-target-only.txt`，内容为 `A00b target-only at T1\n`；`T2` 从 `T1` 只新增 `docs/a00b-target-moved.txt`，内容为 `A00b target advanced to T2\n`。开发提交 `D1` 不变，同一队列条目先后准备 `M1=(T1,D1)`、`M2=(T2,D1)`，各自第一父提交为准备时的目标。

| 断言 | A00b：原生 Git 可核对的输入事实 | A02e：须由产品验证的预期 |
|---|---|---|
| 目录 | `git ls-tree`：`M1` 有 `docs/a00b-target-only.txt`，`D1` 没有；`M2` 有两个目标文件，`M1` 没有第二个。 | Run 绑定 `M1` 时，其 `docs/` 目录页能列出首个目标文件；绑定 `M2` 时能列出两个。遍历相关页，页身份始终与绑定一致。 |
| 文件 | `git cat-file blob`：`M1` 中首个目标文件与样例字节相同，`M2` 中两个目标文件均同样例；两次合并树中的便签查询均使用 `id.desc()`。 | 对相关目标文件请求覆盖完整短文件的范围，返回与对应候选一致的内容、范围和文件摘要；查阅便签查询可见对应的 `id.desc()`。 |
| 差异 | `git diff --name-status` 及补丁：`T1 → M1`、`T2 → M2` 都只修改 `backend/app/routes.py` 中的排序表达式；目标独有文件不在开发差异内。 | 两次差异读取分别使用 `T1`、`T2` 为固定基线；查看相关差异页，只显示上述开发修改及对应位置，不将目标文件列为开发增删改。 |
| 构建输入身份 | Git 对象可核对最终 SHA、第一父提交和树；Git 不判断业务绑定。 | 各候选页面的候选标识、最终提交、基线和清单摘要须一致，并与相同尝试对应的构建输入核对；按记录串联队列条目、尝试、受管 Git 来源与候选 InputSet，不把 Task 来源、候选和报告的 InputSet 当作同一 ID。此项核对身份，无需物理构建。 |
| 目标移动与历史 | 核对两次合并的父提交分别为 `(T1,D1)`、`(T2,D1)`；固定 `M1` 仍指向原树。 | 目标从 `T1` 移到 `T2` 后，旧 `M1` 或其报告不能支持当前采纳；准备 `M2` 后，旧报告不能用于批准 `M2` 或完成 Task。旧尝试及旧报告保持原绑定与结论，不要求新增历史读取入口。 |
| 错 Task 作用域 | Git 不判断 Task 权限。 | 用同项目另一 Task 的验证或审查 Run 请求读取 `M1`：作用域不符，返回拒绝且不返回候选页面或源码内容。 |

本文件只冻结预期。原生 Git 核对结果由 A00b 配套输入记录登记；产品结果由 A02e 另行记录。该资产不构成产品通过、物理构建或人类批准的证据。
