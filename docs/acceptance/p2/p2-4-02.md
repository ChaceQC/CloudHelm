## 撤销计时与故障结果

以下单次观察用于本机诊断，保留原时基和起点；未把代理 UTC 与 Hub UTC 相减，也没有把测量值当成包含时钟误差与任意调度延迟的承诺。

|场景|观察与结果|
|---|---|
|最终 Edge 已有 SSE|UTC `2026-10-29T16:40:54.530Z`～`16:41:04.199Z`，19 项核对完成；从发起真实管理撤销到 Edge EventSource 观察错误为 `1118.679 ms`，随后新请求 403。时基为 Windows Node `performance.now()`|
|两次实际 TLS SSE|UTC `2026-10-29T16:41:26.332591+00:00`、`16:41:27.290255+00:00` 记录撤销请求；本机 `CLOCK_BOOTTIME` 的提前采样到客户端 EOF 分别 `727.824/773.303 ms`，上游活动数归零|
|全局确认|两次 TLS 记录均为 `revoking/pending_time_unknown`，独立确认数为 0；原 10 秒截止已保存。ASGI 本地关闭报告没有被算成独立入口确认，没有生成全局生效时间|
|控制查询挂起|真实 socket 小方法初测最后有效控制到封入口 `3002 ms`；将控制查询超时缩为 1.5 秒后复测为 `2502 ms`，封入口后两端 EOF 各 1 ms。授权/控制失败为合成输入，未取得严格误差上界|
|普通 HTTP/SSE|独立 socket 方法复测从合成撤销到两侧 EOF 均 `899 ms`，封入口到最后 EOF `1 ms`，新请求 403|
|确认响应丢失与新启动代次|合成授权方法中，同一本地事实提交后丢响应，原事实重投两次；新 boot 面对旧授权返回 403、未接触上游、未替旧 boot 报告。实际持久数据库/独立确认丢包和真实代理进程重启未由该方法证明|
