# P2.5-02 单 Agent 早期基线

日期：2026-10-29（Asia/Shanghai）；归档入口 `dev / e4ca8d6`，源码保持 `0.27.0`。本包整理 [A11](p2-1-a11.md) 已有真实单开发 Agent 记录，不重新运行工程、模型或正式验收。原始候选仍绑定各自当轮源码与输入，不因本次归档获得新通过结论。

## 数据与复核入口

[脱敏原始记录](p2-5-02-baseline.json) 保存原始来源摘要、全部已保存尝试、逐请求 usage/费用及工程事实。来源为忽略目录 `.thesis-work/p2-1-a11/` 的安全结果、响应旁录及固定源码映射；公开数据按允许字段提取，不包含凭据、prompt、完整工具参数、代码正文或日志。原始文件的 SHA-256 便于持有原文件者复核，公开字段本身可用于复算，不依赖仍存活的数据库或容器。

费用按 `request_record_id` 去重，多个快照的计算结果取最高 `revision`；重复快照不增加尝试数。不同 Session 的先导失败、暂停或中断分别保留；请求分母包含成功、失败和实际重试，缺失结果不删除。计算金额使用十进制字符串；未知费用保持 null，并另存原预留占账。预留不是实际费用，兼容提供方账单也不等同于官方价格计算金额。

JSON 顶层 `sources` 记录文件身份与 SHA-256，`attempts` 记录各会话及其 Run/工程事实，`requests` 按真实请求身份保存账目；`summary` 为这些字段的汇总，`measurement_limits` 说明未采集项。文件范围是现存安全记录，不表示所有历史尝试均已完整保存。

## 原始字段与指标口径

|范围|本次保留与解释|
|---|---|
|运行及固定输入|尝试、Task、Session、Run 身份，真实结果/原因，InputSet、候选、构建及源码映射引用；保留各次尝试自身配置差异，不把探索轮次合并成相同实验条件|
|增量循环|已有 Run 结果、工具顺序与工程操作引用，可核对读取/修改、自测、候选和构建交接；UTC 观测时间用于定位，不据此恢复未采集的单调耗时|
|构建联调|已有构建身份、状态、退出码、内容核验及工具反馈；操作结果与耗时分别表示，不能从 succeeded 推断性能或完整独立验收通过|
|队列与控制响应|分别保留可得的排队、执行、控制请求与生效时间字段；没有匹配起止或单调计时时为 null/unknown，工具顺序不充当队列延迟或取消响应测量|
|每次真实模型请求|原请求身份、Run、模型/提供方及配置/价格修订、币种、预留、结果修订、usage 原字段、计算金额、账单金额及未知原因；缓存/输入/输出字段缺失不补零|
|人工介入|原 `manual_continuations` 是方法触发普通继续分支的计数，并非独立记录的人工介入事件；初次启动也不计入。主动操作与被动等待分别留存，未采集参与者和起止区间时均为 null，不把继续次数或观察窗口当作人工分钟|

费用覆盖率以“有可核实计算金额的请求数／全部请求数”表达；usage 覆盖率独立按原必需字段是否齐全表达。已知费用小计不是完整总费用；任一请求费用未知时，完整总费用及完整单位交付成本保持未知。独立交付成功数没有采集，不填零；未获得该分母或分母为零时单位成本不可计算，工程交接 submitted 不计作独立验收成功。

后续采集时间时，增量循环/构建联调/队列/控制响应均须绑定原运行或操作身份，分别保存开始、结束、同一计时域的单调耗时及结果/缺失原因。人工事件须保存运行、参与者、目的分类、主动区间与被动等待区间；每名参与者的重叠主动区间合并后相加。主动操作、等待和未记录是不同事实，不以本次归档倒填历史数据。

Run 的 `deadline_at` 是期限，不是完成时间；构建/核验的 `observed_at` 是观察时间，不是物理操作结束时刻。原方法虽然用单调时钟控制超时，但没有保存可比较的起止区间，不能事后从轮询记录恢复精确性能。

## 支持边界

A11 是固定 notes 单文件需求的工程探索，跨轮源码、历史上限、环境和构建配方发生过变化。保留所有已找到记录及观测缺口，只支持这些记录的工程行为、请求账目和采集覆盖说明。墙钟回拨的原限制保留，不提供由 UTC 差值推导的循环/构建/排队/控制性能比较。

[P2.5-03](p2-5-03.md)、[P2.5-04](p2-5-04.md) 和 [P2.5-01](p2-5-01.md) 的验证、审查与返工开发证据单独引用；其中合成模型/阶段结果和上游夹具不混入 A11 真实请求费用、修复耗时或质量样本。正式验证/审查反馈后的真实模型修复全链及主动人工时间未由历史记录补齐。

本包不是 P3.4 冻结后的单/多 Agent 对照，没有独立成功率、缺陷率、节省时间或成本收益结论，也不表示完整 P2、部署、容量、Desktop 原生或人工产品验收完成。后续 P3.4 仍须在采集前完成 D06 §11.1～11.3 的任务、条件、指标、独立判定、预算、起止与失败规则冻结。
