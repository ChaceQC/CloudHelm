## 3. 五项阶段出口的裁决依据

1. **三组接缝与关键不变量。** SDK-01 的同库整体回滚/重投、SDK-04/A01 的原回执与新 Run、SDK-05/A02 的允许内容、SDK-06/A02 的恢复/当前门禁，以及 Compose/Remote 的真实解析/在线许可/账本/计数进程构成直接证据。G02a 已补齐固定参照的逐字段适用性与旧解析器真实拒绝，不以删掉资源/隔离字段制造支持。HTTP 夹具、静态约束、合成向量和真实供应商结果各有范围；这些证据支持 P0 的有限选型判断，不证明新产品集成通过。
2. **首链输入、同机拓扑与支持组合。** 来源、需求、独立资产、源码/方法 InputSet、迁移和九检查点均可追溯；G01a 的真实快照与 G01b 的明确后端/硬限/身份/网络方案已填补同机准备缺项，拓扑、支持矩阵 r3 与参照规格 r2 已接续。未批准额度及未知占用不被写零后放行。另一台目标和实际交付仍属 P1.4/P1 出口前置，现有事实不产生独立部署或容量通过结论。

## 4. 一致性核对与最终收尾

- **资源与存储已对照一致。** G01a 不以聚合用量自称已分配，G01b 选择非稀疏预分配 ext4、独立组后端及全部写入者/子进程硬限，外层实际字节只计一次；旧/新空间并存先占账，保留后端不自动释放。符合 [D03 §4.2～4.4](../../design/03-workspace-build-resources.md) 和资源 r1 的 K/U、D=0 口径；实际安装、ENOSPC、峰值/越界、重启与停止释放仍由 P1.3 的基础设施/资源/执行器负责人取证。
- **身份、许可与预览已对照一致。** 三份机器叶子身份及受限 helper 不继承诊断 SSH/root 权限；管理材料不进入独立预览 TLS 终结，内网 DNS/私有 CA 不忽略证书验证。同机 loopback 仍需 UID/cgroup/namespace 及转发路径拒绝证据，P2 预览原始端口不沿用 P1 loopback 映射；沿用 [D05](../../design/05-security-sync-operations.md) 与既有许可/预览决定。P1 身份/许可负责人、P2 客户端/代理安全负责人分别承担实际启用证据。
- **参照与首次目标边界已明确。** G02a 保留资源、安全、迁移、网络和 DNS 故障语义，拒绝原开发 trust 与直接部署；新增运行约束需要新输入和证据。首次镜像 load、数据库实例/认证/角色及受管卷不是既有五步链的假定成功事实，未有获准副作用步骤就拒绝。P1.2 构建负责人及 P1.3/P1.4 交付/数据库负责人按已登记入口补齐，不隐藏到 `runtime_input_check` 或只下载/校验的 `artifact_prepare`。
- **G03b 仍须完成最终绑定与裁决。** 主会话对最终源码、新 InputSet、历史来源和必要结果进行绑定核对，同步当前出口、估算、计划/进度并记录 CI/Git 实际结论。旧卡、旧 InputSet、历史运行和未知费用不改写。本文件在该次冻结前完成，冻结后的最终来源/验证/放行结果由 [exit-review.md](exit-review.md) 和 [PROJECT_PROGRESS.md](../../../PROJECT_PROGRESS.md) 单独记录，不反向改本文件制造预先通过。
