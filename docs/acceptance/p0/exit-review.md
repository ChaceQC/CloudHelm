## 3. 三组接缝与六卡消费结论

组件锁定与许可证/支持边界见 [组件基线](../../decisions/p0/component-baseline.md)。原 r1 接缝、A01、A02、参照分别消费各自 InputSet；较新方法只证明新候选的所列路径，不追认旧候选。此次没有重跑模型收费批次、旧数据库/容器接缝或参照应用。

|证据|可复用的明确范围|本次决定与仍受限入口|
|---|---|---|
|[SDK-01](SDK-01.md)|同库不同 schema、四个写入点失败整体回滚、受支持事务入队、丢回执去重与异摘要拒绝|复用公开 DBOSClient/SQLAlchemy 接缝；新领域命令仍须 P1 真实接线和唯一约束，不跨数据库声称原子性|
|[SDK-02](SDK-02.md)、[A01](A01.md)、[A02](A02.md)|受支持薄适配的逐次登记/费用门禁，SDK 二次出站夹具，以及恢复后的实际新模型请求|采用当前授权/金额门禁与允许内容引用，不采用未经裁剪的默认 DBOS 包装；未知费用沿原请求继续占账|
|[SDK-03](SDK-03.md)、A01/A02|实际工具事件、供应商函数流、重复/重放去重及严格断流组合|副作用经过 Gateway；未核验供应商工具或服务档位不扩大支持，未知断流结果先核对|
|[SDK-04](SDK-04.md)、A01|历史/延期批次、accepted 独立、实际 Operation 等待/新 Run 的受控同库交接|原 Run 恢复与新 Run 续接映射固定；产品收件箱/Task 当前状态和多人并发仍须 P1～P3 验证|
|[SDK-05](SDK-05.md)、A01/A02|允许引用保留；消费 canary/大对象后成功和失败检查点的受控裁剪|默认原参数/原异常/完整历史入口拒绝；清理默认关闭，引用仍需恢复时不删除|
|[SDK-06](SDK-06.md)、A02|固定单 worker SIGKILL 恢复、已提交结果重取、优先级/查询取消响应，以及恢复新请求门禁|不推出物理容量、多 worker 或跨版本恢复已支持；增加 Runner 不增加 DBOS worker|
|[Compose/Remote 专项](compose-remote.md)|实际 Compose 归一化、两个环境制品不变、受限参数拒绝；loopback 签名许可/本地账本/真实计数进程的重复和失联|三组接缝中的 Hub/Remote 只支持实验范围；初始时间算法不追认为本轮时间协议，s2413 实际认证/配额/停止和完整参照部署待取证|

据此，Runtime/Gateway 与 DBOS/业务状态采用已记录版本下的所选薄适配；Hub/Remote 的工具及实验方法可复用，生产适配入口尚未启用。六卡逐项有有限版本化结论，不将“每卡有一个通过切片”写成整卡或 P0.1 全包无条件完成。

参照源码及独立 HTTP 方法已经固定，实际 [参照验证](../reference/validation-r1.md) 属于本机组合。参照开发 Compose 含 build/ports/资源等字段，旧产品实验子集只接受六类服务字段；P1.2/P1.3 需从固定制品编译经评审的受限运行声明，并核验其拒绝/资源映射。已选接口不会因文档同步自动适配完整参照。
