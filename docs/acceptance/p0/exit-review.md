### 7.3 本轮之后的实际运行门禁

- P1.1 先建立真实身份、当前授权、统一命令事务、Task 和幂等；P0 契约与 JSON Schema 不能替代这些业务实现。
- P1.2/P1.3 落实固定制品、参数化运行声明、受控路径/完整组硬限、唯一占账与全部写入者。未批准额度或未知占用没有可信上界时整组拒绝；不接管当前共享 Docker daemon，不剥离参照安全字段。
- P1.3/P1.4 在有权安装范围内先取得制品加载、数据库实例/角色/受管卷和许可时间的实际前置；不能将初始化或加载藏进只读检查。每个普通新步骤仍在线取得绑定当前状态的许可，未知先核对原 Operation。
- P1.4/P1 出口前另行安排相对 Hub 独立的 Linux 目标；P2 六组预览及双端原生支持、P4 恢复/应急、P3/P5/P6 扩展和研究按原责任门禁实施。本轮同机快照不产生这些验收结论。

责任角色和更细的拒绝/复核点见独立覆盖表、G01b、G02a 与支持矩阵。P0 准备结项不自动启动 P1，不授予远端修改、部署或人类批准。
