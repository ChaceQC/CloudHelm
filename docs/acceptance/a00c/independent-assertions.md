# A00c 单 Agent 任务与操作账本独立断言

断言修订：`a00c-independent-assertions-r1`。依据用户指定的 `docs/architecture/2026-11-19-agent-architecture-detailed-design.md` §10.1、§10.5、§10.6、[参照需求 r1](../../implementation/reference-requirements-r1.md)及下列任务约定，在查看候选实现或运行结果前冻结。

**A00c 输入核对。** 以固定便签参照项目为起点，只开一个开发 Session。由输入负责人登记基准、需求与断言摘要、三种原 Operation 观察及冲突范围、Hub / SDK / 构建配方 / Desktop / 执行器版本、交付目标与权限准备情况。A00c 核对来源和输入；历史观察只对应原操作和原时点。G01 由独立验收方将实际 Git 提交、候选、最终构建制品、方法与运行环境绑定到 InputSet 后收证；D01/D02 的执行与占账行为另按原操作取证。

| 可复现输入与观测 | 后续应看到的行为 |
|---|---|
| 保留[参照独立资产 r1](../reference/r1/README.md)，在当轮固定制品上依原方法重验，结果绑定本轮 InputSet。另用全新的合成数据集，按序 `POST /api/notes` 创建 `A00C Alder`、`a00c ALMANAC`、`A00C Birch`（请求体只含 `title`），记录三次 `201` 响应的整数 ID，后两次 ID 应依次大于前一次。 | `GET /api/notes` 返回 `200` 和按实际 ID 升序的三条，维持省略 `q` 时的原行为。`GET /api/notes?q=AL` 返回 `200`，恰好含前两次创建的 ID，且顺序不变；第三条不出现。`q` 在 `title` 中按字面匹配子串，ASCII 大小写等价；同一组数据请求 `GET /api/notes?q=%25`（字面 `%`）应返回 `200` 和空数组。既有 r1 不覆盖 `q` 和新的标题值。 |
| 执行器确认旧 Run 已交出实际写入权后，人类只把 `frontend/index.html` 的 `<title>` 从「便签参照」改为「便签交付 · A00c」；核对交权时点到交还快照的差异。 | 执行器拒绝旧 Run 或旧写入代次的修改，工作区不因此变化。交还登记快照和新代次，由同一开发 Session 的新 Run 消费并保留该差异。用 Windows Edge 打开当轮候选制品的前端首页，读取 `document.title`，精确等于 `便签交付 · A00c`。这是候选页面检查，无人测结论。 |
| `q=AL` 兼作返工对照。仅做区分大小写匹配的第一候选只会返回 `a00c ALMANAC` 的 ID。 | 若出现该结果，保留第一候选身份及真实失败的请求和响应，或保留基于该固定候选代码的实际审查反馈。新 Run 修复后固定新候选和 InputSet，复验适用的独立断言与标题。不可改断言让第一候选通过，也不可把预设反例当成已发生的失败。 |

**三种操作事实。** 区分各自的观测时点，各绑定原 Operation ID、规范请求摘要、固定输入、执行器、授权与代次、宿主池及预留。具备当前权限和适用代次的同身份同摘要重投，返回原受理或已有结果，不重复启动或占账；同身份异摘要、越权或过时代次须拒绝。操作事实从原 ID 查询，不得用另一操作、另一候选或队列状态替代。

| 原操作样例 | 应成立 | 不可判成通过的情形 |
|---|---|---|
| 构建成功 | `inspect` 能按原身份核对可靠受理回执、进程成功结束和该固定输入实际生成的制品，制品可按原摘要取回；账本按物理结束与实际磁盘去向结算。 | 只有 `accepted`、HTTP `202` 或队列成功；缺少原进程终态、原制品或摘要不符。 |
| 确认物理停止 | 经授权按原 ID 和代次请求停止，分别记录停止请求回执与进程已停证据。确认停止才释放冲突进程额度；磁盘实际回收或连续转入有界保留占用后，才释放对应额度。 | 有停止回执、取消标记或租约到期，但进程仍在或未证实已停；继续占账并阻止冲突操作。半成品不能作为成功制品，停止也不等于回滚。 |
| 执行事实仍未知 | 回执不明、断连或超时且无法确认物理事实时，保留原操作及未确认的占账，阻止冲突操作和依赖其确定结果的推进；只按原 ID 核对，证据到达后再裁决。 | 推定已失败、已停止或已成功，提前释放占账，换 ID 重发冲突请求，或借用其他操作的进程/制品作为证明。 |

**开发、批准与交付各自收证。** 本例未选人测；人工交权和交还不构成人测，也不生成 `passed` 记录。G01 的构建、独立验证和审查须绑定项目队列准备的同一最终候选及准确目标提交；由有权人类批准当前尝试，队列重查目标后合入。仅在必需项有适用证据、会改变完成依据的写操作已收尾且结果明确时，才能完成 Task；重投应取得同一完成报告。开发完成不产生部署许可。启用交付时，另绑定固定 Release、配置与准确 DeploymentPlan，记录有权人类的独立批准及各步骤许可，并按原计划核对实际数据库修订、服务更新与规定的健康窗口。没有独立可用目标或所需许可时，独立交付仍未验证，不以预览、任务完成或受理回执代替。
