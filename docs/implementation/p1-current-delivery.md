# P1 当前控制面与真实交付准备

本文件约束 P1-CLOSE C08/C09 的输入、交接和执行次序，承接用户选择的评估第 3、4 项。工作分解见 [PROJECT_PLAN.md](../../PROJECT_PLAN.md)，实际结果见 [PROJECT_PROGRESS.md](../../PROJECT_PROGRESS.md)。当前源码为 `0.10.0`、工作流应用独立为 `cloudhelm-hub/0.7.0`、业务 head 为 `0011_p1_archive_maintenance`；这三类版本不互相替代。

## 1. 固定输入与前置

- 原 Operation、计划摘要、安装、完整 SQLite/WAL 及物理范围沿用 [C06/C07](../acceptance/p1/archive-closeout.md)，保留原 `unknown` 和有界磁盘占用。
- 原三份 OCI、BuildRun、InputSet、Release 与独立运行证据保持原来源。归档字节相同只证明内容身份，不能将旧验证摘要改绑给新 BuildRun；`runtime_verification_digest` 包含 Build Operation 和输入摘要。
- 旧时钟证明绑定旧启动纪元。当前证明的观测、签名见证、方法和环境在新的本机忽略目录独立保存，不覆盖旧样本、profile 或公钥。
- 禁止整机重启，不恢复或执行旧工作流，不将 accepted、回执接收、停止或本地封闭记成完整部署成功。

## 2. 控制面交接的实际缺口

`initialize` 用于当前空库初始化或同一次初始化的续接，不支持旧业务库升级或历史导入。原回执接收需要同库原 approval、plan、binding、environment revision 和 remote grants。新空库只有安装凭据仍无法通过原身份核对，且其容量查询看不到原保留磁盘。

远端观察也以 binding ID 查询原基线；另建 binding 会看不到原修订。禁止用新 binding、安装或 Operation 绕过原冲突，也不手工补写 passed、许可、事件或成功 BuildRun。

用户已选择原快照的独立维护副本路线，允许为原身份收尾定向恢复和升级；旧工作流保持关闭。下表保留路线差异，不将其混写为已有能力：

|路线|必需工作与边界|
|---|---|
|原快照的独立维护副本|需要用户改变“旧快照只核对”的当前选择。先固定原快照/角色/文件来源和源控制面静止证据，建立受控 `0008 → 0010` 升级与核对；旧工作流全程不启动。原身份回执和当前人类收尾沿原记录处理，新副本不能自动取得普通运行资格。这是有限恢复/维护工作，不宣称完整 P4 恢复。|
|新控制面的正式受信交接|先按 D02/D04 评审保存来源、原身份、当前人类确认、单调修订和同一物理盘保留的交接契约；容量与基线查询真实消费交接记录。旧快照只证明其保存时刻，不能单独当成当前权威历史。旧制品事实也需受支持的适用性交接或新的真实构建/独立验证。当前尚无实现。|

接收方和交接输入落实前，不实际调用 `--closeout-operation`。该命令会先永久封闭本地原身份，再进行物理核对与上传；上传失败不回滚已写封闭。原本地封闭、Hub 接收和当前人类收尾分别留证，旧步骤结果保持原义。

### 2.1 本轮有限维护入口

本轮仅支持固定旧快照的 `0008_p1_4_remote`、相同工作流应用/DBOS SDK/PostgreSQL 基线及本次原 Operation。恢复使用本轮独有隔离实例、新数据库访问凭据和独立目录，不执行旧角色快照中的秘密、不向旧客户端暴露普通入口。先确认原控制面没有运行进程/连接引用，再恢复；恢复后立即由维护角色设置 `recovery_required`，失败也不回到 ready，不调用 DBOS.launch 或 DBOS.migrate。

定向迁移沿现有线性链前进，并新增只供此维护范围使用的不可变来源记录。该记录固定原 Hub installation、Operation、快照摘要、隔离证据摘要及解析出的 project/plan/binding；当前库的实际 Alembic head、应用/SDK/PostgreSQL 基线和记录须一致。迁移不改写原步骤、批准或 DBOS 历史，不将 schema 升级当作恢复普通执行资格。

恢复库普通 API、worker 和许可入口继续被 `recovery_required` 拒绝；仅本机维护入口可在维护角色、准确原身份范围及真实当前认证下接收 C07 回执、执行当前有权人类的幂等收尾。复用既有领域校验、命令结果、事件和保留容量，不为维护另造成功结论或宽泛 readiness 绕过。人类命令仍绑定准确计划/回执摘要；恢复许可不能替代该确认。

限定维护入口的完成不自动开放恢复库普通运行。后续当前控制面接入需先核对原工作流、在途意图和信任，原身份保持封闭；无法完成明确核对的部分继续阻塞，完整 P4 恢复仍另行实施。

### 2.2 当前固定组合的新计划准备

原身份已由当前人类确认收尾后，本轮只建立该固定项目、原 binding 和独立目标的新计划开发组合。普通产品恢复能力不因此开放。组合入口在新数据库访问凭据、原身份永久封闭和当前收尾事实下，核对旧 DBOS 工作流全部终态、旧队列/定时计划为空及旧控制进程静止；不重放旧工作流或通知，不启动人类 Hub HTTP 入口。实际允许的 Remote 通道仅绑定当前项目/目标的新凭据。

新的 Hub 进程生成当前 incarnation/time epoch；目标通过既有受认证 SSH 维护入口接收该固定身份和当前认证材料，沿原完整 SQLite 核对已封闭原 Operation，持久固定当前控制身份并拒绝旧身份新增 grant。新 Agent 的真实进程身份及递增 generation 经同一收尾范围维护登记，保留原计划、修订和磁盘占账。进程存在、当前身份登记和新部署成功分别记录。

组合仅复用经当前 OCI 内容核验且来源链未改绑的原 Release/BuildRun/InputSet，使用原绑定收尾后的空修订 1 生成新计划。当前人类会话在私有本机命令内继续用于该项目计划编制及准确摘要批准，维护身份不自动获得其他产品恢复或通知权限。

本轮时间依据保持为当前 boot/clocksource、连续签名见证及固定测量组合；联合原始样本的区间结论只描述该次观测。在新计划确认材料中显式列出固定组合的时间假设和正式时间验收未完成状态，最终批准前不执行任何新业务步骤，不将开发实测写成长期硬件误差保证。

## 3. 当前时钟输入

硬件 profile 的采样准备可先于数据库路线进行；它绑定实际两端 boot、clocksource、WSL VM、签名见证公钥和方法，不代替后续在线样本对 Hub incarnation、time epoch、执行代次和认证通道的绑定。

原 Windows 见证须能访问实际 HCS VM、注册生命周期回调、订阅电源事件并绑定监听器；进程保持运行至实际步骤结束。不能仅凭非管理员身份推断实际权限失败，也不能以无签名响应代替当前方案。启动前后及采样期间须验证签名、nonce、公钥 pin、见证实例、VM 状态和事件计数，重启见证不能沿用旧 profile。

按 [时间决定](../decisions/p0/time-preview-access.md) 分别核对样本读数误差、相对速率上界及连续性。一次首末采样区间落在 ±100 ppm 内只证明该次观测，不能独自证明适用运行期间的硬件/虚拟化上界。缺少依据时保留未满足状态，普通步骤门禁继续关闭；不调整系统时间、放宽门禁或填入未经证明的数值。

## 4. 新计划与批准后执行

原身份交接、残留容量与当前时钟都满足后，再从实际目标观察固定 Release、配置、secret 版本引用、起始修订、执行身份/代次和资源。五步为归档准备、运行输入检查、数据库迁移、服务更新和健康窗口；每步时限、前后置、安全停止及失败策略随完整计划固定。

呈交完整计划和规范摘要后，由当前有权人类批准该摘要。旧批准和旧截止时间不复用；执行时输入变化或期限失效须重新规划，不能更改已批准正文。

批准后只运行一次必要真实链路；出现 unknown 先查询原 Operation，不重传、重载或另建操作绕过。记录各步许可、接受、意图、真实结果、数据库修订和后置条件；全部步骤及连续健康窗口成立才记部署成功。随后核对重复投递仍关联原操作，验证 Hub 离线后业务继续运行，不执行整机重启。

资源/Task 缺项、4 核 8GB、独立 Runner、Windows 原生和人类产品验收不由本轮代填，P1/P2 出口仍以[出口核对](../acceptance/p1/exit-review.md)为准。
