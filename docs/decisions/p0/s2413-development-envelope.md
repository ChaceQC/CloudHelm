## 2. 受控路径与写入所有权

安装器持有四个顶层目录及挂载点，初选 root:root、0750；仅为对应服务账户添加必要的遍历 ACL。角色数据子树默认 0700、身份材料文件 0600；最终 UID/GID、ACL、挂载来源和允许写入者在安装记录中固定，不沿用诊断 root 或未知旧目录。
服务程序与普通业务 API 不能创建、替换顶层挂载点或修改其他角色子树；发现符号链接、越界路径、已有未登记数据或属主不符即拒绝接管。

|路径|首批用途与所有权|允许写入与拒绝边界|
|---|---|---|
|`/srv/cloudhelm`|root 持有已固定的组件版本与只读制品视图；`workspaces/<resource_group_id>` 仅作受控挂载点|安装/升级通过独立受控操作；Runner 只写其分配文件系统内的工作区，不能写组件、权威 Git 元数据或其他组|
|`/var/lib/cloudhelm`|root 持有存储后端；`hub/`、`runner/`、`remote/` 分别属于对应服务；`allocations/` 的 backing 文件归 root|Hub 保存权威 Git/业务元数据；Runner/Remote 分别保存身份和本地执行记录。数据库目录仅给固定数据库运行 UID；各类数据进入独立有界存储，不共用可写缓存或身份|
|`/var/log/cloudhelm`|角色日志与按分配归属的工作负载日志入口，父目录归 root|日志视图映射到该角色/分配的有界文件系统；记录轮转及峰值，拒绝无界 journald/宿主文件回退。审计只含引用、状态与脱敏事实|
|`/run/cloudhelm`|有界 tmpfs 中的角色 socket、锁和瞬时状态；子目录按单一账户隔离|显式 size 上限并计入相应内存占账；不存持久身份、恢复账本或唯一证据。重启后从持久事实核对，不以目录重建恢复执行资格|

`/run/cloudhelm/emergency` 留给 [既有应急决定](core-boundaries.md#5-本机应急身份与维护门禁)，本轮不创建，其 enabled 继续为 false；普通服务账户不加入应急管理员组。
每个角色独立秘密引用与权限；长期密钥不得进入工作区、镜像、日志、模型或公开配置。Hub 与目标业务的数据库存储隔离；Hub 业务和 DBOS 保持同一 PostgreSQL 数据库的不同 schema。

## 3. 首选磁盘硬限后端

首批选择**预分配、固定大小的独立 ext4 文件系统**：安装侧在获准存储范围建立完整分配且非稀疏的 backing 文件，经受控 loop 挂载提供角色存储和每个 ResourceGroup 的写入空间。当前根 ext4 不需要被假定已有 project quota，也不在本任务中改挂载或启用 quota。
backing 的长度、实际分配块、外层元数据开销与可靠容量来源须先核实并占账；禁止稀疏/自动扩容/未经证明的薄置备超卖。任何后端不能提供这项证据时，该磁盘能力拒绝启用；本修订不静默切换另一种 quota 方案。
每个活动资源组使用独立受控 Docker/构建后端；现有共享 Docker daemon 和 `/var/lib/docker` 不接入项目执行。daemon/containerd/BuildKit 的持久数据、临时目录、镜像层、下载归档、解包、缓存、工作文件、数据库卷和容器日志全部落入该组的固定文件系统。
相关组件的运行目录/tmpfs 另受组级内存硬限；组件自身日志也走已计量落点。禁止回退到宿主 `/tmp`、全局镜像库、共享可写缓存、未知卷、任意 bind 或全局 socket。仅配置 `data-root` 或目录名称不能构成通过。
每组 daemon 是执行器内部的受控执行组件，其进程、容器、构建器及子进程必须处于同一已核验父 cgroup；不拆出新的业务微服务，也不向模型/生成代码暴露 daemon API。原生容器卷 UID 与隔离映射按固定镜像验证，不能临时给不可信代码宿主权限。
可信本机特权 helper 只负责已批准身份下的固定挂载/cgroup/后端操作，校验调用者、允许路径、摘要、代次和当前占账；不提供通用 shell、任意路径或无限额 Docker 代理。业务服务账户不属于宿主 docker 组。
首次核验须覆盖后端 ENOSPC、镜像导入/构建峰值、全部临时/日志写入者、越界写入拒绝及重启后的限额保持。只证明一个容器写满失败、观察目录大小或配置 memory 限制，都不足以放行。
预分配文件的已分配物理字节计一次，不再把内部逻辑字节重复相加；保留整个文件系统时仍按外层实际占用计量。需要缩小保留空间，只能在已封闭写入后以获准的新空间完成转换，旧/新并存峰值先占账，不能在线缩额或先退旧账。

## 4. 一个资源池与逐维零可准入

由基础设施负责人证明物理宿主唯一性，再由 Hub 登记一份 `physical_host_id → host_resource_pool_id`；Runner/Remote 实例和各自 daemon 不另增物理容量。当前尚未生成或注册这些实际身份。
当前同机开发/交付验证组共用一份开发执行预算。平台必要保留、系统/缓存和突发余量先从实测总量中排除；已明确的池外服务占用也只在该口径排除一次，不再计入池内预留或 U。

|维度|冻结的设计边界|本轮实际分配 / 启用条件|
|---|---|---|
|内存|8 GiB light 规划：平台 2、系统/缓存 1、突发 1、开发执行共享上限 4 GiB|不是 s2413 已分配额度。以批准预算与扣除必要保留后的实测总量较小值收紧；当前未批准，零可准入|
|CPU|开发执行共享上限 3000m，初选 quota period 100,000 μs|完整父组 quota 覆盖所有写入/执行组件；6 CPU、低 load 或 shares 不代表额度；当前零可准入|
|磁盘 / PID|分别使用 bytes / task 整数；没有隐含默认额度|实际后端、完整峰值和组级 PID 上限均需单独批准并核验；当前未知，零可准入|
|类别槽 / 互斥键|每池重执行最多 1；普通预览与人测共用最多 1；写权/实例/端口独立判冲突|数量上限不是并发承诺。未启用时槽为 0；未核实冲突对象不接受申请|

沿用资源 r1：`A = 全部未释放预留 + K`，`A + U + 新整组占账 <= min(批准预算, 可分配实测总量)`，`hard_limits <= accounted_vector`；K、U 在账本侧，D=0，不开放容量侧转记。未知上界不能写成 0，当前所有未批准/未知维度与类别保持零新准入。
现有服务、运行/停止容器、镜像、卷、缓存、归档与元数据先建立唯一归属；已排除的池外占用、池内预留、K 与 U 不得漏计或双计。对尚无可靠上界的既有占用关闭新准入，不用本轮 MemAvailable 或根分区余量替代它。
所有 reserved/active/releasing/orphaned 的未释放维度继续占账；Hub API、单 DBOS worker、数据库、代理及执行后端开销均纳入对应平台保留或组预算。增加 Runner 不增加 worker 或复制 4 GiB。
首链三个容器声明合计 896 MiB/1500m 只是源文件子组上限，不是完整资源请求；构建、迁移、代理、加载、tmpfs 与保留字节另按唯一归属计入。其只读根、显式内部网络及全部硬限不能为适配旧解析器而剥离。
本修订维持静态组限，拒绝运行中原位调整。停止后重分配先封闭旧启动路径；未决调整仍按旧/目标逐维较大值占账，不以新身份绕过未知。

## 5. 三份控制身份与本机权限

下列账户名为安装方案，当前尚未创建；均为独立无登录服务账户，不共享私钥、补充组或可写状态。

|角色 / Linux 账户|独立身份与职责|隔离与通道选择|
|---|---|---|
|Hub / `cloudhelm-hub`|Hub 控制实例及受信任 API/单 worker；业务角色仍逐命令判权|只持控制面数据库/Git/自身叶子身份所需权限；无共享 daemon socket，不将数据库凭据下发执行器|
|Runner / `cloudhelm-runner`|独立 machine identity、executor instance 与受限开发/构建职责|只接收其开发范围内操作；通过受限本机 helper 落实资源，不能使用 Remote 身份推进目标部署|
|Remote Agent / `cloudhelm-remote`|独立 installation/machine identity，完整计划的唯一物理步骤推进者|与 Runner 分开凭据和状态；每个普通新步骤在线取得当前许可，不能把同机关系当作授权|

首批选择 TLS 1.3 与独立 X.509 机器叶子证书的双向认证通道；初次短期单次挑战绑定目标、操作者和期限，注册后将证书身份映射到当前角色/范围、Hub incarnation 与信任修订。TLS 成功后仍检查当前权限、吊销/轮换、摘要与代次，不以证书单独授予执行权。
PKI 选择受控私有 CA；根签发材料由基础设施受控来源持有，服务只取得自身叶子材料与必要信任链。实际名称、证书、签发/续期与客户端信任尚无输入，不生成占位“已签发”记录。诊断 SSH 密钥不复用为任何产品身份或应急身份。
Runner 与 Remote 主动建立到 Hub 的各自认证控制通道；不开放通用入站 SSH 部署或 shell API。控制协议保持三端身份区分，本机 helper 另用受限 Unix socket、OS 对端身份及固定动作表授权。
若 P2 启用预览，另设 `cloudhelm-preview` 无登录账户及独立代理身份，只持预览授权核对能力；不保存管理 Cookie、Hub 数据库凭据或 Runner/Remote 叶子私钥。

## 6. 内部网络、API、DNS/TLS 与预览

首批网络使用实例独立 namespace 与显式内部网络，拒绝默认共享桥、host 网络、跨实例直连及默认外网出站；必要依赖由受控 Gateway/制品路径取得。保留首链 `frontend → backend → postgres` 名称解析及固定 DNS 故障边界，不能删除 dns_opt 后沿用旧证据。
Hub FastAPI 先绑定 `/run/cloudhelm/hub/api.sock`（仅 Hub 受信任入口可用）；TLS 控制/管理入口候选为 IPv4 loopback TCP 443，机器路由要求 mTLS，管理路由要求当前用户认证。不同逻辑身份采用安装 descriptor 中的固定名称/路由，不用来源 IP 代替认证。
P1 首链验证前端候选为 `127.0.0.1:18080 → frontend:80`；18080 是实施候选，不是批准或已保留端口，不继承开发 58080。必须纳入环境配置与宿主冲突账本，核实后才绑定；冲突或未批准即拒绝，不自动改端口。backend/数据库均不发布宿主端口。
loopback 不能隔离任意同机进程：项目专用 nftables/namespace 规则结合已登记代理/服务的宿主 UID、cgroup 与实例映射限制访问，同时覆盖宿主 OUTPUT 和容器/外部转发路径。内核或后端不能实现时拒绝启用；不修改无关项目的网络规则。
首批名称解析选择受控内网 DNS，管理站点与预览站点使用不同站点域，每实例独立且不可复用的 HTTPS 主机名。安装方必须给出真实名称、解析范围、私有 CA 信任分发、证书及续期责任；当前均未配置，不把角色名当成真实域名，也不关闭证书校验。
对外入口尚未开放：只有名称/信任/访问方和地址获准并取证后，才在明确 IPv4 地址的 TCP 443 上提供入口。若管理与预览共用入口地址，首选仅按固定 SNI 转发 TCP 的入口，分别送到隔离的管理与预览 TLS 终结进程；管理认证材料不进入预览代理。
预览严格沿用既有 IPv4/TCP 443 入口、平台独占兑换路径及原始端口允许方清单；不开放 HTTP 80 重定向、UDP/HTTP3 或 IPv6。只在 CloudHelm 实例/发布/可达路径验证 IPv6 禁用，不以删除 AAAA 或全机禁用 IPv6 代替隔离。
P1 loopback 验证入口不属于 P2 预览授权入口。P2 需生成独立受控预览运行输入：原始前端 80、后端 8000、开发 HMR 5173 不发布到宿主，数据库 5432 仅供同实例后端及另获授权的迁移；生产/人测不开放 HMR。不得将 G02 原输入删字段后声称已支持新路线。
启用前从获准代理、非授权同机进程、另一沙箱及外部来源覆盖实际 IPv4/IPv6 路径、容器地址、loopback 和全部原始端口；核验获准访问与旁路拒绝。只有代理配置或回环绑定不构成证据，未核验的客户端/地址族/路线保持关闭。
票据只经受保护 POST 兑换，采用已定 Strict 专用 Cookie、禁用 Service Worker 和独立原生 WebView 路线。撤销 10 秒、有效控制间隔 3 秒、关流 2 秒沿用原决定；未取得六组 P2 证据与逐代理关闭确认，不声称预览可用或撤销完成。

## 7. 许可、保留与首次运行前置

同机也沿用 `hub-monotonic-us-v1` / CLOCK_MONOTONIC_RAW、认证样本、独立纪元与连续性身份；许可最长 30 秒、不确定度最多 2 秒、首次接受后含误差的启动上界 5 秒。NTP=yes、loopback RTT 小或共用内核都不能证明时间可信。
实际误差、60 秒样本保持期、暂停/重启检测及原 grant/首次锚点不续期必须按许可决定取证。失信封闭未启动路径，已开始/未知步骤沿原 Operation 查询与安全收束；不能以到期杀 CLI 证明数据库已回滚或资源已释放。
完整组停止或 closed_unstarted 必须封闭晚到启动，才按证据归还进程维度。仍存磁盘字节留在原分配，或通过原 transfer_id 将整笔剩余字节连续转入有界 K；回执丢失保留原账并核对，不开放部分转记、容量侧转记或无占账空窗。
停止容器、删除请求 accepted、卷名消失、GC 期限或队列槽释放均不释放磁盘；以受控后端实际块回收及剩余引用为准。保留状态不授予新增写入，后续复制/元数据/扩张须新准入。
首次产品运行先完成路径/账户/存储/组限/共享账本与注册，再取得完整固定制品、镜像加载、目标数据库实例与受控认证/卷的真实证据。Hub 数据库与目标业务实例分开，运行/迁移/管理角色分权，目标拒绝开发 trust 配置。
服务/角色初始化及镜像 load 必须先界定获准的有副作用步骤及输入；未有支持边界时拒绝，不能藏进只读 runtime_input_check 或只下载/校验的 artifact_prepare。其后才按 G02 编译固定五步链、当前修订/后置检查和完整批准计划；不以 Compose depends_on、标签、healthy 或 HTTP 202 补齐前置。
