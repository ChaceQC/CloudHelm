## 1. 选择与职责

选定 `time_domain = hub-monotonic-us-v1`，使用同一 Hub 授权纪元内的相对单调时间。`issued_at`、`expires_at` 和 Hub 样本都是整数微秒；它们没有 Unix epoch/UTC 含义。选择它是因为许可需要证明相对签发方的有效区间，不需要向普通机器墙钟借用未经证明的绝对 UTC 精度。当前协议不接受 UTC 分支，不允许签发、接受或启动时改换解释。

首批实现配置固定为 Linux 两端 `time.clock_gettime_ns(time.CLOCK_MONOTONIC_RAW)`。Hub 在新 `time_epoch` 建立纳秒起点，以与该起点的差向下取整为微秒；执行器记录同一进程连续性范围内的本地原始单调读数。取整、读数位置及调度误差必须进入下文的读数上界。缺少这个 API 或缺少适用连续性证据的组合不启用。`CLOCK_BOOTTIME` 可参与休眠差异诊断，但不能单独证明虚拟机暂停均可检测，也不用于替换许可时间域。

普通墙钟仅用于日志关联、展示及人工审计，记录明确时区、来源和运行 UTC 时间戳；业务日期仍按 Asia/Shanghai。校准墙钟、NTP 显示同步、改变时区或读数数值相近，都不能建立或恢复许可授权。授权时钟本身、两端相对速率、休眠与虚拟化行为须分别有依据。

|身份/字段|固定含义与变更边界|
|---|---|
|`hub_incarnation`|当前获授权 Hub 控制实例；不能替代时基纪元或资源代次|
|`time_epoch`|Hub 一段连续授权时基的不可复用身份；Hub 进程/主机重启、休眠/暂停恢复或时基来源改变时更新|
|`executor_instance`|当前已注册执行器进程实例；重启不能沿用原实例的单调接受锚点|
|`clock_continuity_id`|执行器本地时钟连续性身份；进程/主机重启、休眠/暂停、回拨、跳变或无法证明连续性时更新|
|`mapping_id` / `sample_nonce`|一次不可变样本记录及其 128 位随机请求标识；正常续样生成新值，历史响应或同 nonce 重投不生成新鲜样本|
|`mapping_epoch`|连续可信的映射序列身份；正常续样可保持，任何失信、样本超龄或证明条件失效均封闭旧纪元并更新|
|`channel_binding_id`|认证上下文中当前 Hub/执行器身份及信任修订的绑定标识；不是秘密或可供客户端声明的授权标志|
|`generation`|资源执行代次，独立于上述时间身份；启动时与当前资源事实精确匹配|

认证来源与身份/撤销规则消费 [身份权限决定](identity-permissions-migrations.md)，本契约不另造身份服务。采样与许可复用当前受认证且完整性受保护的 Hub—Remote Agent 通道。请求含唯一 nonce；响应认证绑定 nonce、Hub/执行器身份、通道绑定、时间域、`time_epoch`、执行器当前映射纪元/时钟连续性身份和 `H_s`，并确保 `H_s` 采自本次请求的处理区间。执行器自行记录 `m0/m1` 及认证结果，不把服务器回填的本地读数当证据。原响应重投只可查询原样本，不能把收到重投的时刻覆盖为新的 `m1`。

## 2. 初始数值与误差公式

以下是 P0 选定的启用上限，不是硬件实测结论。D04 的 30 秒许可初值、2 秒不确定度和 5 秒接受窗口保持原义；其余值用于为误差保留余量。实际依据超过上限时拒绝该环境或样本，不把观测值截断成配置值；改变配置须修订决定、契约及适用证据。

|量|冻结配置|依据与失败门禁|
|---|---|---|
|许可生存期|`0 < expires_at-issued_at <= 30,000,000 μs`，通常 30 秒；计划剩余有效期更短则缩短|沿用 D04 待实测初值；不能超过已批准计划有效期，不能续写原 grant|
|不确定度|`u <= 2,000,000 μs`|D04 的准入边界；无法计算或超限即拒绝|
|首次接受到实际启动|含读数/换算误差的上界 `<= 5,000,000 μs`|D04 的有界启动窗口；投递本地队列不算启动|
|最大样本龄|含误差的经过时间上界 `<= 60,000,000 μs`|把保持期固定为 60 秒；超龄使映射失信，不只延迟这一次请求|
|实测完整往返读数差|`0 <= m1-m0 <= 2,000,000 μs`|完整往返及处理等待一并进入计算，不推定链路对称；超限丢弃样本|
|Hub 样本误差 `e_s`|`1..10,000 μs`|须覆盖读取位置、API 精度及取整/编码；10 ms 是允许的最大配置，不是默认已证明的误差|
|本地每端读数误差 `e_m`|`1..1,000 μs`|两个端点分别计入，须覆盖采样位置、读数精度及微秒取整；未证明即不准入|
|两端相对速率误差 `ρ`|`0..100 ppm`|必须证明适用区间内 `|dH/dM-1| <= ρ/10^6`；包含两端硬件和虚拟化时钟行为。单次短采样不能证明它|

`m0` 是发出请求时本地单调读数，`m1` 是收到本次响应时读数，`H_s` 是受认证 Hub 样本。所有量先按上述微秒单位表示，向上取整函数记为 `ceil`。代码使用整数乘除，避免浮点误差改变开区间边界：

```text
upper_elapsed(x, e, ρ) = ceil((x+e) × (1+ρ/1,000,000))
r_bound = upper_elapsed(m1-m0, 2e_m, ρ)
L0 = H_s-e_s
U0 = H_s+e_s+r_bound

Δm = now_mono-m1
e_elapsed = 2e_m
d_age = ceil((Δm+e_elapsed) × ρ/1,000,000)
age_upper = Δm+e_elapsed+d_age
L = L0+Δm-e_elapsed-d_age
U = U0+Δm+e_elapsed+d_age
T = (L+U)/2
u = (U-L)/2
```

完整往返 `r_bound` 覆盖去程、Hub 等待/处理、回程及两端本地采样误差；本方法不将 RTT/2 声称为单程延迟。`e_elapsed` 覆盖锚点和当前端点读数/单位换算；`d_age` 覆盖两时基相对速率偏差随样本年龄累积的扩张。各项即使部分重叠也保守累加，不相减来制造通过。

当 RTT、`e_s/e_m/ρ` 均在配置上限且样本未超龄时，算术上的 `u` 小于约 1.02 秒，距离 2 秒门禁留有余量；这只是选值一致性计算。真实链路是否能持续满足 RTT、硬件漂移及暂停检测要求仍未证明；失败样本不能提高上限或用旧证明覆盖。

每次首次接受和实际启动前均重新计算 `[L,U]`，必须同时满足 `U-L <= 4,000,000`、`L >= issued_at` 和 `U < expires_at`。用端点直接比较保留半微秒中点的精度；`T+u == expires_at` 即 `U == expires_at` 必须拒绝。

接受窗口使用第一次接受读数 `a`、第一次映射的 `e_a/ρ_a` 和当前映射的 `e_c/ρ_c`：`upper_elapsed(now-a, e_a+e_c, max(ρ_a,ρ_c)) <= 5,000,000`。两份依据须属于同一持续有效证明范围；新样本较小的误差不能抹去首次接受端的误差。名义正好经过 5 秒且仍有正误差时已经超限。

时间证据至少保存上述样本字段、认证绑定/验证结论、支持组合和时钟依据修订摘要，以及本次 `r_bound/e_elapsed/d_age/age_upper/L/U` 的可复算输入与计算结果。`support_evidence_digest` 指向受控证据；没有证据、只填摘要或由客户端自称“可信”都不满足门禁。

## 3. 许可绑定、首次接受与失信恢复

`StepPermit` 固定原 `grant_id`、`operation_id`、`plan_digest`、`step_id`、`input_digest`、执行器实例、Hub 控制实例、资源代次、`environment_execution_id`、控制及授权修订、前序结果和当前实际状态摘要，并认证绑定时间字段、`mapping_epoch`、`clock_continuity_id` 和通道身份。许可请求携带当前映射纪元和本地连续性身份，Hub 原样认证绑定；映射失信后的新纪元因此也拒绝尚未来得及接受的旧 grant，不能靠不传旧接受记录重开它。

`environment_config_revision_id` 固定部署参数/secret 引用的配置修订；`expected_environment_revision_id` 指该步期望的环境执行状态修订，两者不得混用。首次步骤使用计划起始状态；后续步骤消费已登记的新环境修订、活动 Deployment、允许的中间状态及前序后置证据。重投或回报迟到不能让 Hub 跳过实际状态核对。

`PermitGate` 是未来适配器在受控事务/启动锁下取得的可信事实投影：认证、在线取得原 grant、时间证明仍有效、当前授权、暂停/取消与恢复门禁、secret/计划/实际前置条件、资源已预留、维护门禁，以及原步骤确未启动和其他 grant 路径已封闭。缺省为拒绝；它不能由外部请求填写来授予权限。`obtained_online` 证明本 grant 是在线获得的，不代表执行器此刻仍连接；连接丢失后的已接受动作仍只能使用原 5 秒窗口和当前已知门禁，不能承诺离线即时撤销。

本地执行器在唯一启动锁下查询原账本。第一次接受前校验当前绑定及时间区间，持久保存完整不可变原 grant、第一次映射及 `first_accepted_mono_us`；同一 `grant_id` 再投只查询这份记录。`accept_grant(..., previous=原记录)` 不重算接受锚点，同 ID 内容变化拒绝。账本必须保证 grant 接受记录唯一，调用方不得把存在的记录作为 `previous=None` 再次接受；这些存储/锁行为属于后续执行器实现，本次纯函数不声称已提供持久去重。

在实际进程/变更启动边界重新读取当前事实，校验原 grant 时间、首次接受窗口、控制/授权修订、代次、维护门禁和实际前置条件，然后持久登记该步 intent 才能开始。`check_start` 只读取接受记录内的原 grant，正常续样仅换 `mapping_id/nonce` 并更新时间区间；不得重写原期限、原锚点或已封闭的启动路径。intent 已存在、原步骤已开始或结果未知时查询原操作，不使用此函数获得第二次执行权。

|失效事件|必须封闭的对象与行为|
|---|---|
|Hub 进程/主机重启、休眠/虚拟机暂停恢复、时基来源或连续性变化|停止旧纪元签发并更换 `time_epoch`；获知变化的执行器废弃旧映射/未启动许可，不因新纪元数值相近而换算旧 grant|
|执行器进程/主机重启、休眠/虚拟机暂停恢复|更新执行器实例或时钟连续性身份，并更新 `mapping_epoch`；持久账本不能令旧单调锚点有效|
|回拨/跳变、样本超龄、证明条件改变、失去速率上界或无法验证暂停检测|`time_evidence_valid=false`，废弃受影响映射并封闭未启动旧 grant；重新校墙钟或收到一个新样本不能清除失信历史|
|已运行步骤遇到时间失效、许可到期、失联或撤权|不开放后续变更；原步骤按下节安全边界收束并核对，未知时保留冲突锁与占用，不因许可到期强杀迁移|

恢复先按原 `operation_id + step_id` 查询执行器账本、物理进程、服务及必要数据库事实，重新取得当前身份/纪元的可信样本。已开始只查询原结果或安全收束，未知保持 `needs_reconciliation`。只有证明未启动，在本地启动锁下持久封闭全部旧 grant 路径，并重查当前批准、输入、授权、控制和资源，才可请求新的 `grant_id`；Operation/step 身份保持。新映射、新纪元、重连、重投或新 grant 都不能复活旧启动路径。

休眠/暂停是否在新步骤前可靠识别必须由实际 OS/虚拟化组合证明；只比较墙钟、只比较两个单调 API、仅重启进程测试都不构成完整证明。Hub 变化到远端获知并非原子操作，承诺仍受 D04 的原有窗口限制。已经部署的业务按自身运行契约继续。普通许可、补偿或时间失信都不能启用本机应急；应急入口在 P4 专项验证前关闭。

## 4. 有限 PlanStep 与运行边界

首批只编译下列类型，`type_revision="1"`。每步固定 `step_id`、输入引用/摘要、前后置条件摘要、`max_runtime_seconds`、`stop_mode`、原结果 `result_query_ref` 及失败分支。未知类型/版本、超出时长、错误停止方式均在计划编译时拒绝整计划；执行器还须声明该类型/版本已有实际支持证据。类型已定义不等于对应执行器已经可用。

|类型|最大运行预算|到期/取消安全边界|原操作查询所需事实|
|---|---|---|---|
|`artifact_prepare`|600 秒|只下载/校验固定制品；取消传输并核对其进程和临时字节，未确认停止/回收前保留占用；不执行下载内容|固定制品 digest、已验字节/完整性、缓存位置和传输原记录|
|`runtime_input_check`|60 秒|停止后续只读检查；已发检查返回/取消后登记，不输出 secret 值|配置/secret 引用修订、服务/端口/卷/备份及数据库前提的原检查结果|
|`database_migrate`|600 秒|只进入已支持的迁移/事务边界；预算到期停止开启下一条动作，并按数据库支持方式请求停止和核对，不以杀 CLI 或许可到期证明回滚|原迁移 Operation、数据库实际修订链及后置检查；支持模式由 [迁移决定](migration-contract.md) 固定|
|`service_update`|300 秒|只对计划固定服务集合执行受控 Compose 变更；取消不代表 daemon 已停止工作，核对当前服务向量后才结束，不能自动反向更新|原步骤 intent、容器/服务实际版本、配置、执行修订及后置条件|
|`health_verify`|300 秒|停止后续探测并保存已有窗口；未达到完整新鲜成功窗口不能记成功|原观察窗口、探测时间及连续成功/失败事实；旧观测不冒充当前健康|
|`approved_compensation`|300 秒|仅已批准、兼容证据齐全的指定服务恢复/重启；新补偿步骤重新在线取许可，失败停止并核对，不递归补偿|原补偿 Operation/step、可信制品和服务向量；不支持数据库回退、任意 shell、改权限或凭据|

这些时长是允许编译的主动执行预算，不是许可生存期，也不是“过时物理进程必然已经停止”的保证。到期尚不能确认安全停止或结果时保留超时事实、`needs_reconciliation`、锁和资源占用；不能伪造成功/已回滚或自动开始冲突操作。真实超时、停止请求、数据库边界和 Compose 后台动作的确认时长均须后续取证。

每步可选择更短预算，不能超过表中上限。默认失败分支为 `stop_and_reconcile`；选择 `approved_compensation` 必须引用完整计划中预先批准的补偿步骤，不能引用自己；补偿步骤自身只能停止。完整计划编译还须验证补偿目标类型、有限无环依赖和引用存在，不接受模型临时插入、任意宿主 shell 或无限循环。这些计划关系与具体执行适配器不由本文的单步契约代实现。

## 5. 契约、窄检查与启用门禁

[permit_contracts.py](../../../packages/contracts/p0/permit_contracts.py) 复用 `decision_common.py` 的不可变模型与公共标量，提供 `PlanStep`、`PermitBinding`、`TimeMapping`、`StepPermit`、`PermitGate`、`GrantAcceptance`、`time_bounds`、`accept_grant` 和 `check_start`。`P0PermitContracts` 仅供汇总生成 schema，不是运行对象。它没有实现认证服务器、时钟采集器、调度器、持久账本或真实步骤执行器。

[check_decision_permits.py](../../../scripts/p0/check_decision_permits.py) 的 `run_checks()` 使用公开合成值核对有效接受/启动、接受与启动时 `U==expires_at` 拒绝、旧纪元/重启/失信、误差增长/超龄、当前门禁、原 grant/首次锚点不续期、类型和时长上限；失败抛异常。复现入口为：

```powershell
wsl.exe -d Ubuntu-24.04 --cd /mnt/e/Project/CloudHelm -- /home/cloudhelm/.local/bin/uv run --locked --offline python scripts/p0/check_decision_permits.py
```

运行结果由 [进度记录](../../../PROJECT_PROGRESS.md) 及最终冻结输入对应的证据记录。本方法没有读取配置秘密、访问模型/数据库/容器或执行远端实验；合成算术检查不证明通道认证、硬件时钟误差、暂停检测、实际停止、部署或人工验收。

|未决证据|责任角色|阻断入口与下一复核|
