## 1. 首批客户端与域名选择

管理端使用独立管理站点，实例使用另一个受控站点下的独立 HTTPS 主机名；不以同主机不同端口隔离。每个环境实例分配不可复用的预览主机名，重建不能继承旧主机、路由或浏览器存储。安装方提供实际域名、DNS、可信证书和续期方案，并将名称、证书策略、路由映射与允许访问方登记为版本化 descriptor。文中的“管理站点”“实例站点”是角色名，不是声称已经配置的域名。缺少任一项时不签发预览授权。

|路线标识|P0 选定的交付方式|启用证据及当前限制|
|---|---|---|
|`browser_windows_edge`|Windows 11 上的 Microsoft Edge，当前管理页申请后，以顶层 HTTPS POST 进入平台兑换页|固定实际 Windows/Edge 版本和六组证据；当前未验证|
|`browser_linux_chromium`|Ubuntu 24.04 桌面上的 Chromium，采用相同受保护 POST 流程|固定实际发行版/Chromium 版本和六组证据；WSL 或 Codex 内嵌浏览器不代替它|
|`external_windows_edge`|Windows Desktop 只打开管理端的资源查询链接；Edge 在自己的浏览器会话中重新完成管理认证及申请|链接无访问能力；不能把 Desktop 的管理 Cookie、票据或临时账号交给系统打开 URL。单独核验 Desktop→Edge 路线|
|`external_linux_chromium`|Linux Desktop 打开管理端资源链接；Chromium 自行认证、申请及兑换|单独核验实际 Linux 桌面、启动方式和浏览器运行时；当前未验证|
|`tauri_windows_webview2`|独立、无 Tauri capabilities/IPC 的 WebView2 容器，使用新的隔离浏览数据分区；容器内先在平台管理页自行认证，再执行受保护 POST|不从主窗口复制认证材料，不建立向项目页面注入秘密的桥接；WebView2 分区、导航封锁和 Cookie 交付均须原生取证|
|`tauri_linux_webkitgtk`|独立、无 Tauri capabilities/IPC 的 WebKitGTK 容器，在独立数据分区内自行认证及 POST 兑换|逐实际 Tauri/WebKitGTK 版本验证；缺少可靠独立分区或无原生能力边界时关闭，不降级到主窗口|

两种 WebView 的全部页面始终无原生能力。兑换前只允许平台管理认证页和本次固定平台兑换地址；兑换后封闭到该实例 origin，拒绝跳回管理界面、具备原生能力的页面、其他 scheme 和弹窗。需要重新认证时关闭该容器并由受信任 UI 新建，项目脚本不能触发向已有项目页面交付票据。销毁或撤销时清理该实例分区；清理浏览器存储不是服务端撤销证据。

首批 Cookie 候选配置统一选择 `__Host-cloudhelm-preview`、host-only、Secure、HttpOnly、`Path=/`、`SameSite=Strict`，不设置 Domain，不滚动续期。这个值是待验证的 P0 配置选择：D05 §4.2 要求分别验证后冻结支持，本文没有补写该验证。任何路线无法完成 Strict 流程时继续关闭并修订决定，不直接放宽到 None。

## 2. 无 URL 票据的实际交付路线

1. 通知、待办和系统“打开浏览器”只携带不授予访问权的资源标识。管理端 `/preview/start` 可以在查询参数中接收该资源标识，但收到链接仍须当前认证。票据、会话凭据、临时账号和替代访问码不得进入任何 URL 的路径、query 或 fragment，也不得进入剪贴板、通知或模型上下文。
2. 当前认证管理页向 Hub 提交受 CSRF 保护的授权申请。Hub 在短事务内检查实际主体、项目/实例归属、权限、策略修订、当前候选/InputSet/轮次及期限；同申请身份重投查询原记录，不生成新授权或延长期限。票据最长 60 秒，且不超过授权和环境期限。票据仅在当前可信管理文档的易失内存中短暂持有；不写持久 Web Storage、日志、诊断或 UI 文本。
3. 管理页通过顶层 HTML 表单 `POST https://实例主机/__cloudhelm/redeem`，将票据放在受保护请求体。仅接受这个固定平台路径、POST 和规定的表单内容类型；拒绝其他方法、路径附加段、query、fragment、Origin 缺失/null 或非本次登记管理 origin。服务端同时校验一次性申请/CSRF 绑定、目标 origin 和服务端票据绑定；不接受任意客户端提供的上游地址。HTTP 入口、URL 重定向和错误回显不得重新编码票据。
4. `/__cloudhelm/` 为平台独占命名空间，由入口在任何项目路由之前截获。其请求和响应绝不转发项目应用。成功返回不含秘密的、不可缓存的平台完成页，设置专用 Cookie；用户从该页点击同源“进入预览”链接。此处选择新的同源导航，避免把跨站 POST 的自动重定向当作 Strict Cookie 必然可用的依据。实际 Cookie 接收和导航行为仍由逐客户端 P2 证据确认。
5. 完成页不嵌入项目脚本或第三方资源；平台入口禁止缓存秘密请求/认证响应，配置 `Cache-Control: no-store`、`Referrer-Policy: no-referrer`、严格 CSP 和禁止嵌入。管理页面不得把票据交给项目的 fetch、消息处理器或任意项目脚本。兑换后丢弃票据；浏览器的 POST 重投也只会触发已消费拒绝。
6. 首批预览禁用 Service Worker。实例主机首次使用前不得已有注册；入口拒绝 Service Worker 脚本请求、禁止其注册所需的 worker 来源并过滤 `Service-Worker-Allowed`，项目响应不能覆盖平台更严格的 CSP。依赖 Worker/Service Worker 的应用在此子集内不声明支持。P2 必须证明旧 Worker、全站 scope、重定向和失败路径均不能截获平台兑换；仅配置保留路径不足以放行。

平台管理 Cookie 保持在管理主机，绝不发送给预览代理或应用。代理消费专用预览 Cookie 后，去掉该保留 Cookie、平台 Authorization 与内部认证头，才向固定项目上游转发；过滤上游对保留 Cookie 名称和平台认证头的覆盖。项目自己的业务 Cookie 不作为平台授权。管理 API 不允许预览 origin 带管理凭据跨源访问，写命令和人测反馈各自执行当前权限、CSRF 与版本门禁。

上述首次交付不依赖跨域 fetch 读取认证响应，也不开放带管理凭据的预览 CORS。WebView 复用其独立容器中的完整网页流程；没有“主窗口拿票据后给项目 JS”的备用路线。

## 3. 绑定、原子兑换和一次会话

`PreviewBinding` 固定 `authorization_id`、授权修订、实际主体、项目、环境实例 EngineeringRef、策略 EngineeringRef、`preview.access` 权限和单实例作用域。开发预览必须绑定工作区，不能冒充固定候选；固定候选和人测必须绑定候选、InputSet、制品 EngineeringRef。人测另要求 HumanTestSession 与测试轮次。EngineeringRef 的 revision/digest 固定被引用内容；环境引用的 object_id 指环境实例。更换主体、权限、策略、候选、InputSet、制品、环境或轮次均不能沿用原会话。

Hub 只保存受保护的票据校验摘要及状态；真实票据/会话凭据不属于此公开契约。`ticket_id`、`redemption_id`、`session_ids` 是不授予访问权的关联标识，不能据其查询或恢复凭据。

实现时由同一应用事务及授权行锁保护：检查当前授权修订与票据未消费，原子提交票据消费、唯一 redemption 和唯一 preview_session。数据库须对票据→兑换和兑换→会话建立唯一约束，并与撤销事务争用同一权威授权门禁；不得先创建会话再异步消费票据。会话继承整份 binding，绝对期限不超过授权/环境期限，后续请求不续期。每次请求/升级都在转发前取得当前授权及固定映射；先登记客户端和上游流连接，再允许流量。

|结果|冻结行为|
|---|---|
|未提交或事务整体回滚|没有新会话，票据仍未消费；原票据有效且当前门禁成立时才可按原身份重试|
|并发消费同一票据|至多一个事务成功，其余拒绝；不能返回第二份会话或等价新权限|
|已提交但响应或 Set-Cookie 丢失|票据保持已消费；重投不补发凭据、不建新会话。持有已收到 Cookie 的客户端可按原会话查询；只有关联 ID 不能恢复访问|
|提交结果未知|先查原申请/兑换，不把未知当未提交；公开契约不构造“未知但可以再创建”的结果|
|丢失响应后显式重新授权|先撤销原申请、未消费票据和可能存在的会话，并取得所有相关代理关闭确认，再建立新授权；同一个重试不能静默变成重新授权|
|提交成功后、响应送达前撤权|返回的 Cookie 仍必须在新请求门禁被拒绝；事务提交不免除当前授权检查|

人测反馈由其权威服务再次核对主体、HumanTestSession、轮次、候选/InputSet 和当前授权，不能等待网络连接关闭后才拒绝撤权反馈。旧页面及重连不被重新绑定到新候选。

## 4. 原始端口、地址族和获准访问方

首批仅启用受控 IPv4/TCP：客户端到实例 HTTPS 入口为 TCP 443，TLS 在平台入口终止；不开放 HTTP 80 重定向、UDP/HTTP3、IPv6 或其他入口。IPv6 必须在实例网络、端口发布和可达路径中有禁用证据，不能仅不写 AAAA。实际网络地址和授权代理身份由平台生成的 descriptor 固定，项目配置不能自行填地址或修改清单。

|目标/原始端口|只允许的访问方与范围|预览代理处理|
|---|---|---|
|前端 HTTP TCP 80|绑定该实例的已登记预览代理|静态内容经当前授权入口；端口不发布到宿主或其他沙箱|
|后端 HTTP TCP 8000，包括已声明 SSE/WebSocket|该实例已登记代理，以及同实例前端组件|代理登记普通请求、升级和双向流；前端内部转发不能复制平台凭据|
|开发 HMR HTTP/WebSocket TCP 5173|仅绑定该实例的预览代理，且用途必须是 development|HMR 必须使用同一授权入口和同一端口的受控 WebSocket；禁用自动端口回退和额外 HMR 端口|
|数据库 PostgreSQL TCP 5432|仅同实例后端组件|不映射为预览路由；专门的受控迁移操作按独立迁移授权/网络规则实施，本清单不授权它|
|平台控制 HTTPS TCP 443|已登记代理到当前 Hub 控制端的认证连接|用于当前授权、失联检测及确认；不对项目容器开放控制身份或控制 API|

前端 80 与后端 8000 取自固定参照的 Nginx/Uvicorn 配置；5173 是本次固定的开发 HMR 选择。参照 Compose 中现有宿主映射只是开发夹具，不能被继承为产品旁路。生产构建和人测不开放 HMR。未在表中声明的服务、地址族、协议、端口、调用方及跨实例访问一律拒绝；其他沙箱和任意宿主进程不因处在“内部网络”而获得权限。

Runner 用实例级网络、端口发布限制和宿主访问控制封闭原始入口；代理用当前授权门禁控制转发。这两项都必须成立。注册映射绑定实例、实际目标地址、端口、协议、路由期限与代理身份，来自受控 Runner 清单，不能由请求参数指定上游。新增端口、HMR 或流服务须先修订映射/决定并纳入撤销与旁路验证。

`PreviewRawPortAccess` 仅校验给定角色、同实例关系和上述原始端口组合；它不解析任意 IP、不分配网络，也不能证明网络真的隔离。来源身份和 descriptor 必须由受信任注册/执行层解析，不能让外部请求自填角色后获得访问。

## 5. 撤销承诺、时限与两类计时

本条明确完成 D05 §4.4/§7.1 要求的 P0 承诺选择：权威授权事务提交后立即拒绝新签发、兑换和后续授权；跨代理入口及已有连接采用有界关闭目标，界面在逐代理证据齐全前显示“撤销待确认”。不承诺分布式入口在零时间内全部断开。

|配置|本次固定值与不可重置起点|失败行为|
|---|---|---|
|`preview_revoke_timeout`|10,000 ms；从 Hub 撤销事务提交的 `revoke_requested_at` 到全部相关代理拒绝新访问、客户端及上游连接均关闭并收到有效确认|持久保存原始截止时间；到界仍缺确认显示“撤销待确认/超时”，保持拒绝，不记成功|
|`preview_control_max_gap`|3,000 ms；从代理最后一次完整验证当前控制通道、Hub/授权状态的时刻起，不以 TCP 活着、发送 ping 或收到旧修订重复包刷新|达到边界即拒绝新访问并启动关流；明确断开、认证失败或不能取得当前授权时更早进入关闭|
|`preview_connection_cleanup`|2,000 ms；从首次关闭触发起，最迟起点为上述 3 秒边界|先封新入口，再终止已登记的两端连接。过界仍有连接是关闭失败，不能确认|

检测 3 秒加清流 2 秒占用最多 5 秒，剩余 5 秒留给传播、确认和保守测量余量。参数是 P0 的启用条件，不是实测能力；P2 必须证明调度延迟、通道行为与清理实际满足它们。代理整体卡死、断电或控制网隔离不能靠本地定时器自证，仍需有效关闭确认或未来独立核验的隔离证据。

两个计时基准严格分开：

- **Hub 撤销计时**：Linux Hub 在本启动代次的 `CLOCK_BOOTTIME` 上记录提交边界及各确认接收边界，保守经过时间包括事务提交采样、读数、调度和时钟误差。以提交前的采样作为较早锚点覆盖提交开销。`elapsed_upper_ms` 与确认的 `received_elapsed_upper_ms` 是同一 `hub_clock_epoch` 的保守上界；不能把代理时钟读数减去 Hub 读数。`requested_at` 和 `deadline_at=requested_at+10s` 为带时区 UTC 的持久审计/截止记录，不以普通 NTP 状态证明精度。
- **代理控制计时**：每个 Linux 代理用自己的 `CLOCK_BOOTTIME` 和连续性范围记录最后有效控制、首次失败与当前读数。`control_age_upper_ms`/`failure_age_upper_ms` 分别是同一代理时基的保守年龄，必须覆盖原始读数差及读数/速率/调度误差。达到 3 秒关闭新入口，首次失败后 2 秒或最后有效控制后 5 秒达到关流硬边界。重投失败记录不能更新首次失败锚点；代理 UTC 的拒绝/关闭时刻用于审计，不用于跨机相减证明总耗时。

上述 API 与误差测量适用性必须按真实 Linux/虚拟化组合验证。时钟连续性、时间依据或启动代次未知时关闭，不用零误差默认值作证明。Hub 重启保留原撤销和截止记录，不能以重启后的单调零点重新给 10 秒；无法重建原计时证据时保持 `pending_time_unknown`，重新核验关闭范围，原承诺不记通过。代理重启先关闭入口且不恢复任何连接，再核对当前 Hub、授权修订、环境、路由和撤销集合；旧 Cookie、路由文件或连接恢复信息不能自行开流量。休眠/虚拟机暂停后未证明连续性也按未知处理。

## 6. 逐代理关闭与真实状态

撤销事务推进授权修订，固定原始可服务代理集合，保存原 binding、原因与范围。每个身份含 `proxy_id + boot_id`；恢复、替换或新增代理必须先同步当前撤销事实，其可能服务集合只能追加到本次核对范围，不能通过移除失联代理减少待确认集合。

代理先拒绝所有新请求、兑换和升级，再关闭相应路由、会话可用状态及已登记的 HTTP 流、SSE、WebSocket、HMR、客户端和上游连接。确认携带原 binding、新撤销修订、代理启动身份、拒绝/关闭时刻及两侧剩余连接数。相同确认重投仅幂等合并原事实；不能代替另一个代理或不同启动代次。晚到旧修订消息不得打开路由。

|公开状态|成立条件与界面含义|
|---|---|
|`pending`|缺任一代理确认、范围未关闭或仍有连接，且尚未达到截止；显示“撤销待确认”|
|`timed_out`|截止已到且条件仍未齐；显示“撤销待确认/超时”，保留未确认身份和未关连接|
|`pending_time_unknown`|计时依据或 Hub 时基连续性未知；保持关闭和核对，不重置期限|
|`effective`|原始加新增的全部可能服务身份确认路由/会话禁用、两侧连接为零，且最后确认接收上界不超过 10 秒；此事实适用于给定绑定和集合|
|`effective_late`|全部关闭后来终于确认，但最后确认上界超过 10 秒；可以展示“已撤销，关闭超时”，本次时限验收失败|

只有上述全部确认事实齐备才写 `revoke_effective_at`，保守取 Hub 收齐确认的实际时刻。达到控制失联界限、单个代理完成关流、DNS 删除、Cookie 清除、Hub 写库、进程退出或健康检查失败都不能证明全局已撤销。失联代理即使理论上应在 5 秒内自闭，仍保持待确认；本次自动事实评估器不接受“已发隔离命令”代替确认。D05 允许的可靠网络/运行隔离及连接终止替代证据，在没有受控方法和实际证据前也不走自动放行路径。
